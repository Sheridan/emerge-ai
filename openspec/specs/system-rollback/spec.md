# system-rollback Specification

## Purpose
Механизмы возврата системы в рабочее состояние после неудачной установки: снапшот снапшот-ФС (один на запуск, по триггеру tier) и fallback-архив файлов устанавливаемой версии пакета с системным конфигом.

## Requirements

### Requirement: Триггер защиты перед установкой
emerge-ai SHALL создавать точку восстановления перед первым merge только если в merge-очереди есть хотя бы один пакет tier 1–4; для очередей только из rest-tier точки восстановления не создаются. Требование действует в любом режиме запуска — включая обычный запуск без `--pretend`/`--ask`; если состав очереди по тирам определить не удалось, emerge-ai SHALL считать, что защищаемые пакеты в очереди есть.

#### Scenario: Очередь с критичным пакетом
- **WHEN** в очереди есть пакет tier 3
- **THEN** перед первым merge создана точка восстановления

#### Scenario: Очередь только из rest-tier
- **WHEN** все пакеты очереди относятся к tier 5
- **THEN** точка восстановления не создаётся

#### Scenario: Обычный запуск критичного пакета
- **WHEN** выполнено `emerge-ai sys-libs/glibc` без `--pretend` и `--ask` и оператор подтвердил merge штатным вопросом emerge
- **THEN** точка восстановления создана до начала merge

#### Scenario: Тиры недоступны
- **WHEN** классификация плана не удалась, но мутационный прогон продолжается
- **THEN** попытка создать точку восстановления выполнена; при её неудаче merge заблокирован по правилам отсутствующей точки восстановления

#### Scenario: Merge не состоялся
- **WHEN** точка восстановления создана, но оператор отклонил merge (ответ «N»)
- **THEN** созданная точка удалена, система не изменена

### Requirement: Один снапшот на запуск
При поддержке файловой системой снапшотов (btrfs и аналогичные, авто-детект) emerge-ai SHALL создать ровно один снапшот за запуск emerge-ai перед первым merge и SHALL удалить его после успешного завершения запуска.

#### Scenario: Успешный запуск удаляет снапшот
- **WHEN** запуск с created-снапшотом завершился успехом
- **THEN** снапшот удалён

#### Scenario: Отсутствие поддержки снапшотов
- **WHEN** корневая ФС не поддерживает снапшоты
- **THEN** применяется fallback-архив вместо снапшота

### Requirement: Fallback-архив
При отсутствии снапшот-ФС emerge-ai SHALL архивировать файлы устанавливаемой (заменяемой) версии пакета согласно CONTENTS и соответствующие системные конфигурационные файлы; пользовательские данные архивироваться и восстанавливаться не SHALL.

#### Scenario: Архив на ext4
- **WHEN** пакет tier 1 устанавливается на корень ext4
- **THEN** файлы заменяемой версии по CONTENTS и её системный конфиг помещены в архив до merge

### Requirement: Откат по решению пользователя
Восстановление из снапшота или архива SHALL выполняться только по явному решению пользователя (или автономно при флаге ответственности), после показа разбора последствий отката. Канал отката SHALL быть достижим и как отдельный режим — собственный флаг `--rollback` без запуска emerge; предложение отката после неудачной установки поступает в любом режиме запуска с сохранённой точкой восстановления.

#### Scenario: Неудачная установка критичного пакета
- **WHEN** установка пакета tier 1 привела к неработающему состоянию и есть снапшот
- **THEN** пользователю предложен откат с разбором последствий и выполнен только после подтверждения

#### Scenario: Отклонённое предложение сохраняет артефакты
- **WHEN** пользователь ответил отказом на предложение отката
- **THEN** система не изменена, снапшот/архив сохранены

#### Scenario: Режим восстановления
- **WHEN** выполнено `emerge-ai --rollback`
- **THEN** показаны доступные точки восстановления с временем и содержимым очереди; выбранный снимок восстановлен только после подтверждения; emerge не запускался

#### Scenario: Неинтерактивный режим без флага ответственности
- **WHEN** `emerge-ai --rollback` выполнен без TTY и без флага ответственности
- **THEN** ничего не восстановлено, показаны отказ и ручная инструкция

#### Scenario: Автономный откат при флаге ответственности
- **WHEN** сбой очереди tier≤4 с сохранённой точкой восстановления и включённый флаг ответственности
- **THEN** откат исполнен автономно и задокументирован в журнале запуска

### Requirement: Недоступный онлайн-откат
Если откат требует перезагрузки или внешних носителей (например, корневой подтом), emerge-ai SHALL сохранить снапшот/архив до явного подтверждения пользователем и выдать понятную инструкцию восстановления — в том же канале (предложение после сбоя, режим `--rollback`), явно сообщая, что система не изменена.

#### Scenario: Откат root-подрево
- **WHEN** восстановление снапшота невозможно без перезагрузки
- **THEN** снапшот не удалён, пользователю показана пошаговая инструкция восстановления

#### Scenario: Офлайн-случай из режима восстановления
- **WHEN** `emerge-ai --rollback` выбран снимок, требующий офлайн-восстановления
- **THEN** показана пошаговая инструкция, артефакты сохранены, файловая система не изменена
