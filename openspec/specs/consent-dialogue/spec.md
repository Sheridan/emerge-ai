# consent-dialogue Specification

## Purpose
Единый интерактивный consent-диалог перед любой мутацией: нумерованный список исполняемых whitelist-сценариев с контрактом точки восстановления, свободный текст оператора — канал модели, отказ — ноль изменений системы.

## Requirements

### Requirement: Единый consent-диалог перед мутацией
В интерактивном запуске без `--pretend` aimerge SHALL перед любой мутацией (protect, merge, починка) задать единственный вопрос согласия — нумерованный список исполняемых сценариев, каждый с описанием последствий и затрагиваемых tiers. Он заменяет бинарный «Proceed? [y/N]» и молчаливое создание точки восстановления. Для чистого плана список вырождается до сценария merge плюс выходы; для деградированного — включает сценарии починок (из находок план-триажа) и сценарий «merge как есть» с указанием, какие пакеты в план не попадут. До явного выбора не SHALL быть создано ничего: ни точки восстановления, ни правок, ни merge-прогона.

#### Scenario: Чистый план в интерактиве
- **WHEN** интерактивный `aimerge -uDN @world` получил чистый план из 12 пакетов
- **THEN** показан список с единственным исполнительным сценарием merge (12 пакетов, тиры) и выходами; до ответа оператором точка не создана, emerge без pretend не запускался

#### Scenario: Деградированный план
- **WHEN** вердикт план-триажа «деградировано» (конфликт, маска, world-файл)
- **THEN** список содержит по сценарию на каждую починку плюс «merge как есть» с перечнем исключённых пакетов; выбор сценария починки исполняется системой, затем план пересобирается и диалог продолжается

#### Scenario: Plain-интерактив больше не молчит
- **WHEN** интерактивный запуск без `-a` дошёл до мутации
- **THEN** consent-диалог задан; ответ «abort» завершает прогон без единого изменения системы и с ненулевым кодом

#### Scenario: Неинтерактив без диалога
- **WHEN** прогон с `--noninteractive` (или не-TTY) дошёл до мутации
- **THEN** вопросов нет; матрица автономности и аудит принимают решение как раньше, точка восстановления создаётся автоматически по триггеру тир

### Requirement: Все варианты диалога исполняемы
Каждый пронумерованный вариант consent-диалога SHALL быть исполняемым сценарием из белого списка: текст пункта механически связан с typed-действием apply-канала (рендер из typed-спека, исполнение через единственную точку мутации с аудитом). Вариантов «сделайте руками» в списке не существует; advice, не исполняемый системой, печатается вне нумерованного списка. Модель вправе упорядочивать, группировать и комментировать варианты, но SHALL NOT сочинять исполняемые действия, отсутствующие в белом списке.

#### Scenario: Нет ручных пунктов
- **WHEN** для находки не существует исполняемого действия белого списка
- **THEN** она не входит в нумерованный список, а напечатана отдельной строкой «система это пока не исполнит»

#### Scenario: Текст пункта = действие
- **WHEN** оператор выбирает пункт «unmask dep: add … to package.accept_keywords»
- **THEN** исполняется ровно то правка-действие, из которого отрендерен текст пункта, и оно записано в журнал решений

### Requirement: Свободный текст оператора возвращается модели
Ответ оператора, не являющийся номером, SHALL передаваться агенту в тот же контекст разбора; агент SHALL ответить/уточнить/перестроить варианты (по-прежнему только typed) и переспросить. Раунды диалога (раунд = один ответ оператора) SHALL NOT быть ограничены по числу; счётчик раундов не печатается. Гарантированные выходы доступны в каждом раунде: вариант abort, EOF, ctrl-c — все означают «ничего не исполнять».

#### Scenario: Уточнение текстом
- **WHEN** оператор вместо номера ввёл «а jemalloc нельзя без масок обойтить?»
- **THEN** агент разобрал вопрос в том же контексте и задал новый вопрос с обновлённым списком вариантов; система не изменилась

#### Scenario: Устал — вышел
- **WHEN** оператор выбрал abort на пятом раунде диалога
- **THEN** прогон завершён без изменений системы; ни один раунд ранее не был прерван лимитом

### Requirement: Точка восстановления — часть контракта согласия
Вопрос consent-диалога SHALL включать блок контракта точки восстановления (содержание и честность раскрытия — требование «Контракт точки восстановления в интерактивном согласии» спеки `system-rollback`). Блок печатается до создания точки: в момент показа вопроса на диске не SHALL быть ни снапшота, ни архива по этому прогону.

#### Scenario: Блок до создания
- **WHEN** consent-диалог показал блок с путём снапшота для очереди tier≤4
- **THEN** до ответа оператора снапшот/архив по этому прогону не создан; после «y» точка создаётся первой операцией
