# run-reporting Specification

## Purpose
Информационное обогащение работы emerge-ai: enrich фазы плана (`-p`/`-a` с оценками времени и дайджестом), автоматический doctor на world/system, пост-запусковый дайджест и changelog собранных пакетов.

## Requirements

### Requirement: Enrich для pretend/ask
При флагах `--pretend`/`--ask` emerge-ai SHALL напечатать штатный вывод emerge без изменений и добавить обогащение: детерминированное ядро (genlop-оценка, tier-распределение) и LLM-сводку плана. Вход LLM-сводки SHALL включать severity-срез вывода план-фазы (спека plan-triage); при вердикте «деградированный план» сводка SHALL поимённо перечислять пакеты, которые не попадут в merge, и причину каждого пропуска, а не ограничиваться констатацией пустого плана. Значения ядра печатаются без изменений; при ненастроенном endpoint или сбое LLM сводка SHALL опускаться без прерывания план-фазы. Финальный вопрос о продолжении SHALL задавать emerge-ai только при `--ask` без `--pretend`; при активном pretend вопрос не задаётся и продолжение не происходит.

#### Scenario: Претенд с оценкой
- **WHEN** выполнено `emerge-ai -p sys-devel/gcc`
- **THEN** после списка emerge показаны оценка времени и дайджест изменений

#### Scenario: Ask с подтверждением
- **WHEN** выполнено `emerge-ai -a @world`
- **THEN** после вывода emerge с обогащением emerge-ai задал вопрос «Proceed?», при «y» установка продолжилась

#### Scenario: LLM-сводка поверх ядра
- **WHEN** endpoint LLM настроен и план собран
- **THEN** после строк ядра (tier-распределение, genlop-оценка) показана LLM-сводка, а значения ядра напечатаны без изменений

#### Scenario: Без endpoint — только ядро
- **WHEN** LLM endpoint не настроен и выполнено `emerge-ai -p app-editors/vim`
- **THEN** показано детерминированное ядро, LLM-блок отсутствует, предупреждений нет, вопрос о продолжении задан штатно

#### Scenario: Сбой LLM не рвёт план
- **WHEN** LLM-вызов сводки завершился ошибкой или таймаутом
- **THEN** показаны строки ядра, план-фаза продолжается, вопрос «Proceed?» задан

#### Scenario: Ask с pretend не спрашивает
- **WHEN** выполнено `emerge-ai -a -p @world`
- **THEN** показан обогащённый pretend-вывод, вопрос не задан, install-прогон не выполнялся

#### Scenario: Сводка по деградированному плану
- **WHEN** план-фаза вернула `Total: 0 packages` при запросе обновления с пропусками (конфликт, маска)
- **THEN** LLM-сводка называет пропущенные пакеты и причины вместо «No packages are listed in the plan»

### Requirement: Автоматический doctor
При сборке world/system или массовом world-апдейте emerge-ai SHALL автоматически выполнить preflight: dry-run резолвера, риск-тирование merge-листа, предупреждения о критичных пакетах и суммарную оценку времени; preflight выполняется в любом режиме запуска — включая обычный запуск без `--pretend`/`--ask`, до начала слияний; отдельной командой doctor не является. Информационные блоки preflight SHALL NOT попадать в stdout мутационного прогона — в stdout остаётся только вывод emerge.

#### Scenario: Док на world
- **WHEN** запущен `emerge-ai -uDN @world` с пакетом tier 1 в плане
- **THEN** до начала слияний показан doctor-отчёт с предупреждением о tier 1

#### Scenario: Обычный запуск без флагов
- **WHEN** запущен `emerge-ai -uDN @world` без `--pretend`/`--ask`
- **THEN** doctor-отчёт показан до подтверждения и начала merge, stdout содержит только вывод emerge

#### Scenario: Одиночный rest-tier пакет
- **WHEN** запущен `emerge-ai app-editors/vim`
- **THEN** doctor-отчёт не показывается

### Requirement: Пост-запусковый дайджест
При включённой опции конфига emerge-ai SHALL после завершения показать дайджест: что собрано/установлено и какие действия выполнил агент.

#### Scenario: Дайджест есть
- **WHEN** опция дайджеста включена и запуск изменил 5 пакетов с одним вмешательством агента
- **THEN** показан дайджест из 5 пакетов и описание вмешательства

### Requirement: Changelog-дайджест собранных пакетов

При включённой опции emerge-ai SHALL для собранных пакетов извлекать changelog из локальных источников (news, GLESA, диффы USE) и внешних: release-changelog GitHub/аналогов, коммиты и merge-записи git-репозитория проекта; LLM SHALL отбирать самое важное и заметное. Дайджест SHALL печататься plain text и сохраняться в отчёт соответствующего прогона; ручной вызов `--changelog` SHALL оставаться работоспособным.

#### Scenario: Changelog с релизов
- **WHEN** у пакета есть GitHub-релизы и опция включена
- **THEN** changelog-дайджест содержит ключевые изменения между старой и новой версиями

#### Scenario: Источник недоступен
- **WHEN** у пакета нет доступного changelog-источника
- **THEN** в дайджесте указано отсутствие changelog, ошибка не генерируется

#### Scenario: Дайджест в отчёте прогона
- **WHEN** changelog-дайджест построен в ходе прогона
- **THEN** текст дайджеста сохранён в отчёте этого прогона наряду с прочими его данными

### Requirement: Автоматический changelog-дайджест после прогона

После успешного прогона, в котором были собранные пакеты, при включённой опции `changelog_digest` emerge-ai SHALL автоматически построить и напечатать changelog-дайджест этих пакетов и сохранить его в отчёт прогона; при ненастроенном LLM endpoint дайджест SHALL деградировать до сырого перечня собранных событий; при выключенной опции автоматический changelog-дайджест SHALL не выполняться и не создавать сетевых обращений.

#### Scenario: Автовызов после обновления
- **WHEN** опция `changelog_digest` включена и `emerge-ai -uDN @world` завершился успешно
- **THEN** после дайджеста прогона напечатан changelog-дайджест, отдельная команда не требовалась

#### Scenario: По умолчанию тихо
- **WHEN** опция `changelog_digest` не настроена и прогон завершился успешно
- **THEN** changelog-дайджест не строится, внешних обращений нет, вывод прогона не изменился

#### Scenario: Без endpoint — сырой перечень
- **WHEN** опция включена, LLM endpoint не настроен и прогон успешно собран
- **THEN** напечатан сырой перечень доступных changelog-событий без LLM-отбора, без ошибки

#### Scenario: Сбой дайджеста не портит прогон
- **WHEN** при построении changelog-дайджеста произошло необработанное исключение
- **THEN** код возврата прогона не изменился, в stderr напечатано предупреждение
