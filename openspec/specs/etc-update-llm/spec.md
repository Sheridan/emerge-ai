# etc-update-llm Specification

## Purpose
Обработка защищённых конфигурационных файлов (config-protect) после сборки: LLM готовит решение по каждому файлу с опорой на документацию пакета, пользователь подтверждает, применение атомарно по одному пакету.

## Requirements

### Requirement: Обработка config-protect после сборки
При наличии опции «etc-update после сборки» включённой, aimerge SHALL после установки пакетов обнаружить все защищённые изменённые конфиги и передать их на разбор агенту; при выключенной опции — показать список изменений без действий.

#### Scenario: Опция выключена
- **WHEN** в конфиге `etc_update_after_build` выключен и появились config-protect файлы
- **THEN** aimerge показал список, изменений на диске нет

### Requirement: Решение LLM по каждому конфиг-файлу

Для каждого защищённого файла агент SHALL подготовить решение «оставить / выбросить /
смержить» с обоснованием и ссылкой на источник документации пакета (man, info, файлы
`/usr/share`, веб-поиск при включённом web-доступе). Веб-контекст SHALL загружаться
фактически — страница каталога пакетов по `<категория>/<пакет>` из пути файла либо поиск по
вики Gentoo; при недоступности сети веб-контекст SHALL становиться пустым с предупреждением
в stderr, а решение по файлу — готовиться как обычно.

#### Scenario: Новая опция в конфиге

- **WHEN** апстрим добавил в конфиг параметр, отсутствующий в локальном файле
- **THEN** агент предлагает смержить параметр с цитатой из документации

#### Scenario: Веб-доступ выключен

- **WHEN** в конфиге `agent.web_access` выключен
- **THEN** веб-запросы не выполняются вовсе, решение готовится по локальным источникам

#### Scenario: Веб-нет недоступен

- **WHEN** `agent.web_access` включён, но запрос к каталогу/wiki завершился ошибкой
  (сеть недоступна, страница не найдена, истёк тайм-аут)
- **THEN** в stderr выведено предупреждение, веб-контекст пуст, LLM-решение по файлу
  вынесено и показано пользователю как обычно

#### Scenario: Ошибка веб-фазы не подменяет ошибку LLM

- **WHEN** веб-загрузка завершилась любой ошибкой
- **THEN** сообщение об ошибке LLM (`etc LLM unavailable`) НЕ печатается, пакет не
  пропускается молча

### Requirement: Подтверждение и атомарное применение по пакетам
Каждое решение SHALL подтверждаться пользователем до применения; применение SHALL быть атомарным — один пакет за раз, следующий пакет не обрабатывается, пока не завершён текущий.

#### Scenario: Отказ по одному пакету
- **WHEN** пользователь отклонил предложенное решение по пакету A из трёх
- **THEN** конфиги пакета A не изменены, обработка перешла к пакету B

#### Scenario: Откат решения на подтверждении
- **WHEN** пользователь изменил предложенное решение (например, вместо «смержить» выбрал «оставить»)
- **THEN** применено пользовательское решение, агент показал итоговый эффект

### Requirement: Язык обоснований

Обоснования решений по конфигам SHALL даваться на языке, настроенном для ответов агента.
Директива этого языка SHALL передаваться и в system-часть, и в prompt слияния конфигов, а не
только в prompt главного агента; машинная часть решения (формат ответа, коды действий) при
этом остаётся неизменной.

#### Scenario: Русский язык

- **WHEN** в конфиге язык ответов `ru`
- **THEN** разбор конфигов выведен по-русски

#### Scenario: Немецкий язык

- **WHEN** в конфиге язык ответов `de`
- **THEN** обоснование LLM-решения по конфиг-файлу выведено по-немецки, действие и
  применение решения работают как обычно

#### Scenario: Автоопределение по локали

- **WHEN** язык в конфиге не зафиксирован (`auto`) и системная локаль `ru_RU.UTF-8`
- **THEN** разбор конфигов выведен по-русски

### Requirement: Обработка config file needs updating из план-фазы

При находке план-триажа `IMPORTANT: config file ... needs updating` aimerge SHALL предложить исполнение через существующий etcupdate-канал: разбор конкретного файла (оставить/выбросить/смержить с обоснованием) и атомарное применение по файлу с бэкапами etcupdate. Применение SHALL требовать согласия в интерактивном запуске (consent-диалог/гейт) и не выполняться автоматически в неинтерактиве — там находка печатается в отчёте без действий. Настройка `etc_update_after_build` на эту ветку не влияет: она управляет пост-сборочной обработкой config-protect.

#### Scenario: Исполняемый вариант из план-фазы

- **WHEN** план-фаза показала `IMPORTANT: config file '/etc/portage/package.env/lto' needs updating`, запуск интерактивный
- **THEN** среди исполняемых вариантов есть применение обновления этого файла с обоснованием и бэкапом; до согласия файл не тронут

#### Scenario: Неинтерактив не применяет

- **WHEN** та же находка получена с `--noninteractive`
- **THEN** файл не изменён, находка отражена в отчёте прогона

#### Scenario: Отдельно от post-build опции

- **WHEN** `etc_update_after_build` выключен, а в план-фазе есть находка needs updating
- **THEN** исполняемый вариант план-фазы доступен (в интерактиве по согласию) — опция его не блокирует
