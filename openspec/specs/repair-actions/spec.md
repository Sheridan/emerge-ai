# repair-actions Specification

## Purpose
Замкнутый белый список исполняемых починок: род «белая команда» с фиксированными argv-шаблонами, бэкапом, аудитом и механическим undo; исполняемые варианты по классам находок план-триажа; ньюз-дайджест GLSA/news как read-only действие.

## Requirements

### Requirement: Закрытый белый список исполняемых починок

Каждое исполняемое действие emerge-ai SHALL принадлежать закрытому перечислимому белому списку: род, цель, параметры, идемпотентность или обязательный бэкап перед исполнением, аудит-запись и механически выводимый текст отмены. Модель SHALL заполнять только валидируемые слоты шаблонов (cpv, атом, keyword-строка); произвольные argv, пути или команды от модели не исполняются никогда. Каждое действие применяется только через существующий apply-канал (согласие/матрица, аудит, единственная точка мутации).

#### Scenario: Нет свободной команды

- **WHEN** модель предлагает «выполнить» строку, не являющуюся экземпляром шаблона белого списка
- **THEN** действие не исполняется; предложение может быть напечатано только как текст вне исполняемых вариантов

#### Scenario: Отмена в consent-формулировке

- **WHEN** consent-формулировка варианта с правкой `package.accept_keywords` показывается оператору
- **THEN** в ней указан способ отмены, определяемый видом механически (удаление строки с аудит-маркером emerge-ai)

### Requirement: Род действий «белая команда»

Белый список SHALL поддерживать род «исполнение белой команды»: фиксированный argv-шаблон с валидируемыми слотами, идемпотентность или бэкап, аудит до исполнения. Первые действия рода: `emaint --check world` — read-only диагностика, доступна агенту как инструмент исследования; `emaint --fix world` — перед исполнением SHALL создавать копию world-файла с именем, содержащим `emerge-ai` и идентификатор прогона (если копии этого прогона нет), исполнение повторяемо, отмена — восстановление копии; `emerge --deselect <атом>` — слот валидируется как фактический член world-сета, отмена — `emerge --noreplace <атом>`, зафиксированный в аудите.

#### Scenario: Мир-файл чинится с бэкапом

- **WHEN** выбран вариант «fix world file (emaint --fix world)»
- **THEN** копия world-файла создана до модификации, команда исполнена с фиксированным argv, запись в журнале решений содержит путь копии

#### Scenario: Deselect только члена world

- **WHEN** атом варианта отсутствует в world (например, был убран параллельным прогоном)
- **THEN** действие отклонено валидатором слота до исполнения, система не изменена, вариант помечен неактуальным

#### Scenario: Проверка мира — инструмент, не мутация

- **WHEN** агент в разборе вызывает `emaint --check world`
- **THEN** вывод возвращается как результат инструмента, файловая система не изменена, consent не требуется

### Requirement: Исполняемые починки по находкам план-триажа

Для каждого класса находок план-триажа белый список SHALL иметь хотя бы один исполняемый вариант: маска зависимости пропущенного пакета — правка `accept_keywords` с exact-атомом и keyword; конфликт с установленным — `accept_keywords`/`use`-правка или deselect виновного атома; проблемы world-файла — `emaint --fix world`; `config file needs updating` — применение etcupdate по конкретному файлу (спека etc-update-llm). Отчёт и consent-диалог SHALL NOT печатать «система это пока не исполнит» для находок, покрытых этими вариантами.

#### Scenario: Живой кейс закрыт целиком

- **WHEN** обработан прогон с находками edk2-bin/qemu (конфликт), yazi/jemalloc (mask), world-файл, `package.env/lto needs updating`
- **THEN** каждая находка имеет исполняемый вариант меню; ни одна не помечена «не исполняемо»

### Requirement: Ньюз-дайджест как read-only действие

При наличии непрочитанных элементов GLSA/news emerge-ai SHALL исполнить чтение сам (список и тела непрочитанных — read-only) и включить LLM-дайджест (сущность, затронутые пакеты из плана/мира, срочность) в отчёт; текст «прочитайте вручную» без содержимого не SHALL считаться обработкой. При недоступном LLM печатается детерминированный список (заголовок, дата, id).

#### Scenario: Дайджест вместо приглашения

- **WHEN** в прогоне есть непрочитанные новости, endpoint настроен
- **THEN** отчёт содержит дайджест каждой непрочитанной новости; команда `eselect news read` оператору не предлагается
