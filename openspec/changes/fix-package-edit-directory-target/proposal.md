# Proposal

## Why

Канал правки `package.*` (`config_edit.apply_package_edit`) предполагает, что
`/etc/portage/package.<kind>` — файл, и открывает его на append. На хостах с
каталожной раскладкой Portage — а это штатная рекомендация Gentoo и фактическая
раскладка рабочего хоста, где `/etc/portage/package.accept_keywords`,
`package.use`, `package.mask`, `package.unmask`, `package.env` являются
каталогами с файлами по категориям, — прогон падает с `IsADirectoryError`
**после** того, как оператор дал согласие: строка не записана, emerge не
перезапущен, вместо починки — traceback. Тот же допущение тихонько ломает
отмену: `remove_by_run` обходит только файлы `package.*` и на каталожном хосте
не находит ни одной строки прогона.

## What Changes

- Правило разрешения цели записи: если `package.<kind>` — каталог, строка
  пишется в `package.<kind>/<category>`, где `<category>` — категория атома из
  строки (`=dev-libs/jemalloc-5.4.0-r2 ~amd64` → `package.accept_keywords/dev-libs`);
  если это файл или отсутствует — поведение не меняется (append в файл, файл
  создаётся). Существующая раскладка хоста никогда не переписывается.
- Детерминированный резерв, когда категория из строки не выводится (wildcard
  `*/*`, set-атом `@world`, вообще не-атом): строка идёт в зарезервированный
  файл `emerge-ai` внутри того же каталога — append с аудит-маркером, ничего
  не затирается. Никогда не пишется «файл вместо каталога» и вне `/etc/portage`.
- Обход каталогов для отмены и обзора: `remove_by_run` и
  `get_package_edit_lines` рекурсивно читают файлы внутри `package.*`-каталогов;
  идемпотентность, «только строки с маркером этого прогона» и «пустые файлы не
  удаляются» сохраняются.
- Показ цели оператору: detail-строка consent-формулировки и строка активности
  называют фактический путь (`package.accept_keywords/dev-libs`), а не только
  вид правки, — до и после исполнения видно одно и то же место.
- Неизменно: append + аудит-комментарий `# emerge-ai: <дата> <run-id> <reason>`,
  единственная точка мутации через apply-канал, идемпотентность по дубль-проверке.

## Capabilities

### New Capabilities

- нет

### Modified Capabilities

- `repair-actions`: новое требование «Канал правки `package.*` понимает
  каталожную раскладку» — разрешение цели записи по факту файловой системы
  (каталог → файл категории, файл → append), резерв для строк без категории,
  рекурсивный marker-based обход при отмене и обзоре, совпадение показанного и
  записанного пути в consent-формулировке.

## Impact

- `src/emerge_ai/config_edit.py`: новая чистая функция разрешения цели
  (`resolve_package_target`) + разбор категории из атома; `apply_package_edit`,
  `remove_by_run`, `get_package_edit_lines`, `undo_text` — поверх неё.
- `src/emerge_ai/consent.py`, `src/emerge_ai/cli.py`: проброс `etc_dir` в
  `consent.menu_specs`, чтобы detail/undo-строки называли реальный файл.
- Тесты: `tests/test_config_edit.py` (каталог/файл/резерв/отмена в каталоге),
  `tests/test_consent.py` (формулировка с путём),
  `tests/test_cli_integration.py` (end-to-end: stub-flip по файлу в каталоге).
- Docs: README (раздел про apply-канал и `/etc/portage`) + запись в
  LIVE_CHECKS для проверки на каталожном хосте.
- Не затрагиваются: белый список команд, etcupdate-канал, оверлей, точки
  восстановления.
- Вне области этого change (отмечено, не чинится): вид `accept_license` пишет в
  `package.accept_license`, который portage не читает (portage читает
  `package.license`) — отдельный дефект маппинга «вид → имя файла», не связанный
  с каталожной раскладкой.
