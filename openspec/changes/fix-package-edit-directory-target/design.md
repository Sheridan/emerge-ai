# Design

## Context

Мотивация — в proposal.md (Why). Здесь — состояние канала, которое определяет
подход.

- `config_edit.apply_package_edit(kind, line, ...)` строит цель как
  `Path(etc_dir) / f"package.{kind}"` и открывает её на append. Никакой
  проверки типа цели нет: на каталоге `open()` даёт `IsADirectoryError`, и
  выше по стеку её никто не перехватывает — в consent-диалоге
  (`cli._consent_execute` → `gate.apply_variant` → `variant.action()`)
  исключение выходит наружу и роняет прогон после того, как согласие уже
  получено и зааудировано. В цикле починки инцидентов тот же путь закрыт
  широким `except Exception` в `_incident_flow` — там вместо починки печатается
  «repair loop skipped».
- `remove_by_run` перебирает `Path(etc_dir).glob("package.*")` и пропускает
  не-файлы (`if not target.is_file(): continue`) — на каталожной раскладке
  отмена не находит ни одной строки прогона и молча возвращает пустой список.
  Вызовов `remove_by_run` из `src/` пока нет (только тесты) — то есть дыра
  отмены станет видна ровно тогда, когда канал начнут отменять.
- `get_package_edit_lines` читает один файл того же имени и на каталоге падает
  тем же `IsADirectoryError`. Воспроизведено локально на tmp-корне с каталогом
  `package.accept_keywords`: apply → `IsADirectoryError`, `remove_by_run` →
  молча `[]`, `get_package_edit_lines` → `IsADirectoryError`.
- Дубль-проверка перед записью в `cli._apply_action` уже обходит
  `Path(etc_dir).rglob("*")` рекурсивно — для каталожной раскладки она
  работает сегодня и менять её не нужно.
- Хост, на котором воспроизведён сбой: `package.accept_keywords`, `package.use`,
  `package.mask`, `package.unmask`, `package.env` — каталоги с файлами по
  категориям (`dev-libs`, `app-misc`, …); Portage читает такую раскладку
  рекурсивно (`recursive=x.portage1_directories` в managers'ах UseManager /
  KeywordsManager), файл `package.accept_keywords` рядом с каталогом не нужен.
- Единственная точка мутации — `gate.apply_variant`; `variant.action()` не
  возвращает результат, решение диалога (`"applied"`) выводится из факта
  вызова, а не из успеха записи.

## Goals / Non-Goals

**Goals:**

- Одна детерминированная функция разрешает «вид правки + строка + `/etc/portage`»
  в путь цели; её же результат показывается оператору до согласия.
- Ни одна правка не превращается в исключение, выходящее за apply-канал:
  недоступная цель — напечатанный отказ с путём и причиной.
- Отмена и обзор видят строки прогона в каталожной раскладке.

**Non-Goals:**

- Не чиним соответствие «вид → имя файла» (`accept_license` против читаемого
  portage `package.license`) — отдельный дефект, отдельный change.
- Не внедряем new-style `packages.*`, не мигрируем и не переименовываем
  существующие файлы пользователя, не трогаем `/etc/portage/patches`.
- Не добавляем новых white-команд, флагов и полей конфига.

## Decisions

### D1. Разрешение цели — чистая функция, вызываемая и для показа, и для записи

`config_edit.resolve_package_target(kind, line, *, etc_dir) -> Path`:
каталог → `package.<kind>/<category>`; иначе (файл или отсутствует) →
`package.<kind>`. `apply_package_edit` пишет в её результат, `undo_text` и
detail-строки consent называют тот же путь. Альтернатива — вычислять путь
только в момент записи и печатать его постфактум: отвергнуто, потому что
consent-формулировка показывает место правки до согласия, и расхождение
«показали `package.accept_keywords`, записали `…/dev-libs`» оператор обязан
видеть сразу.

Раскладка выбирается по факту файловой системы (`Path.is_dir()`, symlink
следится), а не по конфигу: хост с файлами остаётся хостом с файлами,
поведение существующих тестов (и `test_cli_integration` со stub-файлом
`package.accept_keywords`) не меняется.

### D2. Категория — через `tiers.package_of`, имя файла — со своей проверкой

Категория берётся из первого токена строки: `package_of(token).split("/")[0]`.
Существующий `tiers.package_of` — уже единственный нормализатор атома в
проекте (тиры, whitelist-проверка членства в @world); второй regex для
«категории имени файла» неизбежно разъехался бы с ним на operator-префиксах и
слотах. Результат дополнительно проверяется шаблоном `[A-Za-z0-9+._-]+`:
wildcard (`*/*` → категория `*`), set-атом (`@world` → нет `/`) и прочий мусор
не дают категории.

Отказ от `portage.dep.Atom`: канал не должен зависеть от импорта portage ради
чистой операции над файловой системой, а `Atom` на wildcard/set'ах бросает
исключение — то есть возвращает нас к исходному дефекту.

### D3. Нет категории — зарезервированный файл `emerge-ai` внутри каталога

Строка дописывается в `package.<kind>/emerge-ai`. Имя выбрано, потому что
(a) оно уже используется проектом как «файл emerge-ai» в этой же директории
(README советует `package.accept_keywords/emerge-ai` для keyword'ов оверлея) и
(b) append с аудит-маркером безопасно соседствует с пользовательскими
строками. Альтернативы: отказать в записи wildcard-строки (тихий отказ хуже
предсказуемого места — typed-варианты wildcard не порождают, строка сюда
попадает только из модели/парсера), и имя с префиксом `_`/`zz-` (чище по
сортировке, но portage не сортирует файлы каталога значимым для нас образом, а
смысл имени — узнаваемость, не порядок).

### D4. Недоступная цель — отказ канала, не исключение выше apply

`apply_package_edit` поднимает `config_edit.ChannelError(path, reason)` когда
цель существует, но не обычный файл (например подкаталог с именем категории),
или когда append/создание дали `OSError` (нет прав, read-only ФС).
`cli._apply_action` перехватывает его и возвращает
`{"status": "rejected", "reason": ...}` с напечатанной причиной — тот же
контракт, что у TOCTOU-отказа слот-валидатора (whitelist-repair-commands D2).
Сообщение содержит путь и причину; `IsADirectoryError` наружу не выходит
никогда.

### D5. Отказ канала засчитывается в цикл починки

В отличие от TOCTOU-отказа (там состояние может измениться параллельным
прогоном, цикл не «тратится»), отказ канала записи сам не рассасывается:
`_incident_flow.bound()` засчитывает такой цикл в `run.repair`, чтобы
`REPAIR_LIMIT` ограничивал повтор в неинтерактиве. В интерактивном диалоге
повторный показ того же варианта — штатный путь (раунды не ограничены по
дизайну consent-dialogue D5), и оператор выходит через `q`; отказ называет
путь и причину, так что выход из повторного показа не требует разбора кода.

### D6. Обход `package.*` при отмене и обзоре — один обход на оба

Общая генерация целей (`_package_files(kind|None, etc_dir)`): файлы `package.*`
как сейчас + все файлы внутри каталогов `package.*` (рекурсивно, `rglob`).
`remove_by_run` правит только файлы с совпадением маркера этого прогона
(идемпотентность и «пустой файл остаётся» — как сегодня), `get_package_edit_lines`
показывает строки всех файлов категории с той же пометкой «аудит/не аудит».
Обход ограничен префиксом `package.` — `/etc/portage/patches`, `env`,
`savedconfig` и `repos.conf` не читаются и не пишутся.

### D7. `undo_text` и detail — с необязательным контекстом цели

`undo_text(kind, *, line=None, etc_dir="/etc/portage")`: без `line` — прежняя
формулировка по виду (существующие вызовы и тесты не меняются), с `line` —
называет разрешение из D1 (`… from package.accept_keywords/dev-libs`).
`consent.menu_specs(..., etc_dir="/etc/portage")` получает тот же каталог, что
и apply-канал (cli уже знает `etc_dir`), чтобы «edit:»/«undo:» и анонс
активности `editing <path>: + <line>` говорили об одном файле.

## Risks / Trade-offs

- [Цель «до показа» и «при записи» может разойтись: каталог создали или удалили
  между раундами] → разрешение выполняется заново при записи, анонс печатает
  фактический путь; обе цели легальны, разрыв не опасен, повторный показ меню
  показывает актуальную формулировку.
- [Файл категории — пользовательский, с его строками] → только append; отмена
  удаляет строго строки с маркером этого прогона, файл переписывается лишь
  при наличии совпадения; тест держит «соседние строки целы».
- [`remove_by_run` переписывает файл целиком (`write_text`), нормализуя
  переводы строк] → риск ограничен файлами, где есть маркер этого прогона
  (то есть куда писали мы); поведение не меняется относительно файлов,
  расширяется только множество обхода.
- [Имя `emerge-ai` внутри каталога уже занято пользователем] → append, а не
  затирание; строки различимы аудит-маркером, отмена трогает только их.
- [Каталожная раскладка `package.<kind>/<cat>/<pn>` (файлы на два уровня)] →
  запись идёт на уровень категории (плоско, как в рекомендациях Gentoo), отмена
  и обзор рекурсивны и видят оба уровня; разнобоя в записи нет — мы пишем
  только в один.
- [Молчаливый пропуск `package.<kind>`-каталога остался в других местах кода] →
  обход вынесен в одну генерацию (D6), новые места обязаны её использовать;
  в задачах — grep-проверка, что прямого `etc_dir / "package.` не осталось
  вне `config_edit`.

## Migration Plan

Аддитивно, без конфигов и миграций: на файловой раскладке поведение
не меняется (существующие тесты закрепляют это), на каталожной вместо падения
появляется запись в файл категории. Откат change — обычный revert коммита:
старое поведение возвращает `IsADirectoryError` на каталожных хостах, данных
не трогает.
