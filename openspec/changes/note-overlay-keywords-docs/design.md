# Design

## Context

Packaging: единственный ebuild —
`packaging/app-portage/emerge-ai/emerge-ai-9999.ebuild` (`EAPI=8`,
`DISTUTILS_SINGLE_IMPL`, `distutils-r1` + `git-r3`,
`EGIT_REPO_URI=https://github.com/Sheridan/emerge-ai.git`,
`EGIT_BRANCH="master"`, без `KEYWORDS`; live-статус даёт git-r3/версия 9999,
явного `PROPERTIES="live"` в файле нет). Секция «Установка» README `:8-31`
уже описывает этот ebuild корректно: копирование `packaging/app-portage/emerge-ai`
в оверлей, `ebuild …/emerge-ai-9999.ebuild manifest`, echo
`app-portage/emerge-ai **` в `package.accept_keywords`, `emerge -1av`.
Несовпадений имён файлов/команд нет. Remaining gap — только объяснительный
слой (L6): различие `**` vs `~arch` и live-риски.

## Goals / Non-Goals

**Goals:** пользователь понимает, почему без `accept_keywords` пакет не
виден, чем `**` отличается от `~amd64`, и что ставится HEAD `master`, а не
воспроизводимый релиз; изменения только текстовые, аддитивные.

**Non-Goals:** правка ebuild (`KEYWORDS`, `EGIT_BRANCH` master vs
default-ветка, отдельный стабильный ebuild) — кандидаты отдельных changes;
автоматизация генерации Manifest в оверлее; переписывание корректных шагов 1–4;
изменение остального README.

## Decisions

**D1. Только аддитивные правки.** Шаги 1–4 уже соответствуют дереву — не
трогаем; добавляем примечание к шагу 3 и live-блок после шага 4.
Альтернатива «переписать секцию целиком» — diff без необходимости, мешает
бисекту истории README.

**D2. Примечание про keywords — оба варианта.** Для ebuild без `KEYWORDS`
корректных варианта два: `app-portage/emerge-ai **` (принять все архитектуры,
уместно для live git-r3) и явный `~amd64` (частный случай одной архитектуры).
В README сейчас только `**`; добавляем `~amd64` как альтернативу с одним
предложением про различие, чтобы не толкать пользователя к избыточно широкой
маске. Альтернатива — добавить `KEYWORDS="~amd64"` в ebuild: это правка
packaging, вне скоупа.

**D3. Live-предупреждение с практическим выходом.** Короткий блок: ставится
HEAD `master`, Manifest генерируется локально (`ebuild manifest`),
фиксация коммита — `EGIT_COMMIT` в копиях ebuild или патче оверлея. Плюс
одна строка про известный вопрос packaging: `EGIT_BRANCH="master"` при
default-ветке `main` (в этом репозитории фактически `master` — согласовано,
но вопрос зафиксировать). Без блока пользователь считает установку
воспроизводимой. Альтернатива — не упоминать: L6 прямо просит recall про
`~arch` и live-природу; отвергнута.

## Risks

- [README устареет при изменении packaging] → текст перечисляет файлы «как
  есть» (один ebuild), без обещаний на будущее; чеклист change предполагает
  перечитать packaging-дерево перед публикацией.
- [`**` рекомендован без предостережения] → в примечании явно: широкая маска —
  осознанный выбор для live-пакета, вариант `~amd64` показан рядом.
