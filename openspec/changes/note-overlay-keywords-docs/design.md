# Design

## Context

Packaging: единственный ebuild — `packaging/app-portage/emerge-ai/emerge-ai-0.1.0.ebuild`
(`EAPI=8`, `EGIT_REPO_URI=https://github.com/corsair-sys/emerge-ai.git`,
`EGIT_BRANCH="master"`, наследует `git-r3`, `PROPERTIES="live"`, без `KEYWORDS`).
README же описывает два ebuild (стабильный + «live-версия (9999)») и команду
`ebuild …/emerge-ai-9999.ebuild manifest` (`README.md:10,21`). Версия `0.1.0` при этом
live — версия в имени ничего не фиксирует, что дополнительно нужно объяснить.

## Goals / Non-Goals

**Goals:** инструкции установки точно соответствуют файлам в репозитории; пользователь
понимает, почему пакет «не видится» без `accept_keywords`, и что ставится HEAD, а не
релиз; изменения только текстовые.

**Non-Goals:** правка ebuild (KEYWORDS, `EGIT_BRANCH` master vs default-ветка `main`,
настоящий live-9999-файл) — кандидаты отдельных changes; автоматизация генерации
Manifest в оверлее; изменение остального README.

## Decisions

**D1. Документируем реальность, а не желаемое.** Альтернатива — дописать в README
инструкцию для создаваемого `emerge-ai-live-9999.ebuild`: документ снова разошёлся бы
с деревом, пока файл не появится; отвергнута. Если live-9999 появится, README правится
следом за packaging-change.

**D2. Примечание про keywords — оба варианта.** Для ebuild без `KEYWORDS` корректных
варианта два: `app-portage/emerge-ai **` (принять все архитектуры, уместно для live
git-r3) и явный `~amd64` (уже есть в README `:28-30` — оставить, показав как частный
случай). Дать оба с одним предложением про различие, чтобы не толкать пользователя к
избыточно широкой маске. Альтернатива — добавить `KEYWORDS="~amd64"` в ebuild: это
правка packaging, не docs; вне скоупа.

**D3. Live-предупреждение с практическим выходом.** Короткий блок: ставится HEAD
`master`, Manifest генерируется локально (`ebuild manifest`), фиксация коммита — через
`EGIT_COMMIT` в копиях ebuild или патче оверлея. Без этого пользователь считает
`0.1.0` воспроизводимым релизом. Альтернатива — убрать упоминание версий: потерялась
бы связь с именем файла; отвергнута.

## Risks

- [README снова устареет при изменении packaging] → текст сформулирован так, что
  перечисляет файлы «как есть» (один ebuild), без обещаний на будущее; задача-чеклист
  change предполагает перечитать packaging-дерево перед публикацией.
- [`**` рекомендован без предостережения] → в примечании явно: широкая маска — осознанный
  выбор для live-пакета, alternatives с `~arch` показаны.
