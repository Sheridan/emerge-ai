# Design

## Context

- `LIVE_CHECKS.md:26-29` — пункт `## 14.2 Полный live-сценарий (после группы 14)`: регрессия кластерного `-a` (`-av` не должен печатать emerge-овский «Would you like to merge these packages?»), команда напечатана как `emerge-ai emerge-ai -av` (`LIVE_CHECKS.md:27`).
- Удвоение уникально: `grep -rn 'emerge-ai emerge-ai'` по репозиторию даёт только эту строку плюс цитату в описании дефекта `REVIEW_NOTES.md:189`.
- Формат LIVE_CHECKS — прозаический чек-лист для ручного прогона на живой Gentoo-машине, машиночитаемым не является.

## Goals / Non-Goals

**Goals:**
- Чек 14.2 становится исполняемым как записан: оператор копирует команду и получает заявленную проверку.

**Non-Goals:**
- Ревизия остальных пунктов `LIVE_CHECKS.md`, изменение формулировок ожиданий, правки кода/тестов.

## Decisions

### D1: правим только командный токен
Меняем `emerge-ai emerge-ai -av` → `emerge-ai -av` в той же строке; текст про «вопрос задаёт только emerge-ai», «ответ `n` → abort, rc=0» и регрессионную скобку остаётся дословно. Альтернатива «переписать пункт целиком» — создаёт diff без необходимости и мешает бисекту истории чек-листа.

### D2: цитату в REVIEW_NOTES не правим
`REVIEW_NOTES.md:189` дословно цитирует дефект — это запись о найденном, она остаётся историчной; закрытие фиксируется только пометкой L1 (как и в других изменениях).

## Risks / Trade-offs

- Практический риск нулевой: файл никто не парсит; единственный consumer — глаза оператора.
- Оставить опечатку дешевле, но тогда чек-лист врёт именно в регрессионном пункте, завязанном на разбор `-av` — тот сценарий, где «скопировал и запустил» критичен.

## Migration Plan

Однострочный diff в документации; история git сохраняет исходное состояние.
