# Spec Delta

## ADDED Requirements

### Requirement: Применение решения после сбоя

После сбоя emerge предложенные агентом варианты решений SHALL предъявляться
пользователю через гейт согласия; при выборе варианта и подтверждении
оператора решение SHALL применяться, после чего исходный сбойный вызов
emerge SHALL повторяться для проверки починки. Неподтверждённое решение не
должно изменять систему; при отказе пользователя вывод и код выхода
остаются такими же, как при консультационном режиме без применения.

#### Scenario: Подтверждённое применение

- **WHEN** emerge упал, агент предложил устранимый вариант, пользователь подтвердил его
- **THEN** вариант применён, показан код восстановления, исходный emerge повторён, и при успехе прогон завершён кодом 0

#### Scenario: Отказ оператора

- **WHEN** пользователь отклонил все предложенные варианты
- **THEN** состояние системы не изменено, предложение сохранено в выводе, прогон завершён кодом сбоя emerge как до изменения

#### Scenario: Неинтерактивный rest-tier

- **WHEN** запуск с `--noninteractive` упал на сбое, единственный вариант относится к rest-tier
- **THEN** вариант применён без вопроса с показом обоснования матрицы, затем исходный emerge повторён

### Requirement: Ограничение числа повторных попыток

Петля «применение решения → повтор merge» SHALL выполняться не более 2 раз
за прогон; после исчерпания лимита программа SHALL показать отчёт о
нескольких неудачных попытках и завершиться кодом последнего сбоя emerge,
не запуская новый цикл.

#### Scenario: Два неудачных повтора

- **WHEN** применённые решения не устранили сбой дважды
- **THEN** новый цикл агента не запускается, показан финальный отчёт с обеими попытками, код выхода равен коду последнего сбоя emerge
