# Proposal

## Why

Мейн-спек `consent-dialogue` требует, чтобы свободный текст оператора уходил агенту «в тот же
контекст разбора» и агент «ответил/уточнил/перестроил варианты», но реализация отправляет
однократный JSON-only вызов без истории и без инструментов с промптом, запрещающим ответ:
вопрос «для чего нужен edk2-bin?» получил отказ «входные данные не описывают назначение» —
и упал с `AttributeError` (`Response` вместо dict), оборвав весь запуск. Цель проекта —
помогать оператору добиваться установки пакетов; consent-диалог должен быть советником
«как сделать, чтобы запрошенное установилось», а не сортировщиком пунктов.

## What Changes

- Свободный текст consent-раунда становится раундом диалога: история сообщений сохраняется
  между раундами и сжимается при приближении к лимиту (старые раунды заменяются детерминированным
  дайджестом уже применённых починок и последних реплик); каждый вызов получает актуальный
  список вариантов и уже применённые ремонта.
- Канал диалога получает существующий read-only набор инструментов агент-петли
  (`read_file_window`, `grep_log`, `journal_search`, `web_fetch`, `pretend_emerge`,
  `check_world`) через `run_tool_loop` в песочнице; инвариант не двигается: мутация возможна
  только выбором номера через `gate.apply_variant`.
- Промпт канала: сначала ответить на текст оператора (вопрос, уточнение, предложение), затем
  при необходимости упорядочить варианты по ключам; схема `{comment, order}` сохраняется,
  разбор нечувствителен к форме ответа.
- `consent_analyze`: чтение ответа из `Response` (не dict-контракт), любое исключение канала
  деградирует к заметке над меню — запуск не умирает (сегодняшний `AttributeError` — пример).

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `consent-dialogue`: новое требование «Советнический ответ на свободный текст» рядом с
  «Свободный текст оператора возвращается модели»: контекст между раундами (сжатие к
  лимиту), ответ тексту оператора до перестройки вариантов, read-only инструменты разбора,
  нерушимость диалога при любом сбое модели/канала.

## Impact

- Код: `src/emerge_ai/consent.py` (промпт/канал/разбор), `src/emerge_ai/cli.py`
  (`consent_analyze`: состояние истории, `Response`, широкая деградация), возможно
  `src/emerge_ai/llm.py` (переиспользование `run_tool_loop` без правок).
- Тесты: `tests/test_consent.py`, `tests/test_cli.py`; секция живой проверки в `LIVE_CHECKS.md`.
- Поведение: ответы модели в consent-раунде становятся содержательными и помнят контекст;
  latency канала растёт (инструментальные раунды) — осознанная цена цели проекта.
