# Design

## Context

- План-фаза (`cli.py:326-357`) сначала прогоняет emerge с `--pretend` и печатает вывод дословно (`cli.py:333`, требование спека run-reporting), затем вызывает `plan_fn` = `build_plan` (`cli.py:349`), который внутри делает полный второй резолв (`plan.py:49-55` → `portage_compat.resolve`). Замечание L5 (REVIEW_NOTES.md:208-212): на big world — два резолва, заметно по времени.
- Первый прогон уже содержит весь merge-список в pretend-выводе. Парсер такого вывода в проекте есть: `digest.parse_installed` (`digest.py:10-22`) — regex-строки `[ebuild ...] CPV` и `>>> Emerging (...) CPV`, со снятием ANSI; формат давно обкатан на фейках и replay-фикстурах (`test_digest.py:7-8`, `test_agent.py:428-436`).
- Формат CPV различается: резолвер отдаёт `cat/pkg-1.0`, pretend-строка — `cat/pkg-1.0::gentoo`, плюс «установлено» в квадратных скобках (`[1.2]`) после CPV. Тир-классификация (`tier_service.classify`) и `package_of` ждут форму резолвера.
- Наблюдаемое поведение менять нельзя: вывод emerge, дайджест плана (`plan_digest`), doctor, `run.plan` в persisted-состоянии, rc.

## Goals / Non-Goals

**Goals**
- Один резолвер на прогон на основном пути: merge-список извлекается из уже перехваченного pretend-вывода.
- Критерий приемки «вывод и поведение не меняются»: план-записи (cpv, tier, tier_source), дайджест, doctor, rc — идентичны сегодняшним при том входе.
- Деградация безопасна: любой непонятный вывод → нынешний путь с вторым резолвом.

**Non-Goals**
- Не убирать сам `--pretend`-прогон (он — дословный вывод по спеке) и не оптимизировать резолвер.
- Не менять форматы `run.plan`/репортов; не трогать вывод doctor/дайджеста.
- Не добавлять кэширование резолва между прогонами.

## Decisions

**D1. Извлечение — реюз парсера `digest` с нормализацией.** Новая `build_plan_from_output(output, emerge_args, tier_service, *, fallback=build_plan)`: ANSI-strip, regex-множество `digest` (константы переиспользуются, не дублируются), отсечение `::repo`, дедуп с сохранением первого вхождения, тир через тот же `tier_service.classify` (в том же `in_system_set=False`, как сегодня). Альтернатива — собственный парсер — отвергнута: два парсера одного формата разъедутся при первом же изменении вывода emerge.

**D2. Fallback срабатывает на пустом разборе.** Если из вывода не извлечено ни одного CPV, функция вызывает `fallback` (текущий `build_plan`). Это покрывает и `-qq`-вывод, и «реально нечего ставить» — оба случая сегодня дают идентичный результат через резолвер, а цена второго резолва на пустом мире ничтожна. Альтернатива «доверять пустому разбору» отвергнута: молчаливая потеря плана при смене формата хуже лишнего резолва.

**D3. Точка замены — одна строка в CLI.** `cli.py:349` вызывает `build_plan_from_output(output, emerge_args, tier_service)`; логика fallback живёт внутри plan-модуля, инъективный `plan_fn` сохранён для тестов. Альтернатива (ветвление в CLI) отвергнута: CLI не должен знать о форматах вывода.

**D4. Эквивалентность фиксируется парными тестами, а не декларацией.** На одном pretend-фикстуре сравниваются `build_plan_from_output` и `build_plan` с резолвером-стабом, возвращающим тот же список: совпадают упорядоченные entries. Плюс replay e2e: байтовая идентичность stdout/stderr и `run.plan` до/после изменения.

## Risks / Trade-offs

- [Drift формата pretend-вывода (новый emerge, `--quiet`-кластеры) → план тише или пуст] → пустой разбор = fallback на резолвер; непустой парсится консервативно первыми токенами; replay-тесты на фикстурах ловят регресс в CI.
- [Резолвер включает в altlist то, чего нет в pretend-выводе (например, маскированные зависимости) → расхождение плана] → pretend и резолвер вызываются с одними аргументами в одном процессе; фикстурные пары в тестах сравнивают оба пути построчно.
- [`::repo`-суффикс/скобки просочатся в `tier_service` → неверные тиры] → нормализация централизована в одном месте + unit-тесты на маскированные и slotted-строки.
- [Пересечение с `plan-before-plain-merge` (тот же pre-merge блок)] → изменение — одна строка вызова; порядок применения: любое, но конфликт ограничивается этой строкой.
