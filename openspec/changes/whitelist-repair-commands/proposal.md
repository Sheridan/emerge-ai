# Proposal

## Why

Принцип «пока оператор работает с emerge-ai, все действия выполняет система» упирается в узкий белый список: apply-канал умеет только правки `/etc/portage` (use/accept_keywords/accept_license/mask/unmask/env) и оверлей-копии. Находки живого прогона чинятся действиями вне списка: `emaint --fix world` (испорченный world-файл), `emerge --deselect <атом>` (конфликтный атом в world), etc-update для `IMPORTANT: config file ... needs updating` (канал etcupdate существует, но подключён только после merge-сбоя), `eselect news` (оператору до сих пор предлагается читать ньюз руками). Пока этих действий нет, consent-диалог вынужден печатать «система это пока не исполнит» ровно там, где пользователь ждёт починки.

## What Changes

- Белый список исполняемых действий становится закрытым перечислимым множеством с обязательными свойствами каждого действия: fixed argv/параметры из шаблона (модель заполняет только валидируемые слоты), идемпотентность или бэкап перед правкой, аудит-запись, готовый текст «как отменить», входящий в consent-формулировку варианта.
- Новый род действий «исполнение белой команды» с первыми членами: `emaint --check world` (read-only диагностика, песочница агента), `emaint --fix world` (с обязательным `cp world world.emerge-ai.bak` перед исправлением), `emerge --deselect <атом>` (атом валидируется как член world).
- Канал etcupdate подключается к план-фазе: находка `IMPORTANT: config file ... needs updating` становится исполняемым вариантом (применение по файлу через существующий etcupdate-механизм с бэкапами), не только пост-merge обработкой.
- Чтение ньюза становится исполняемым read-only действием с LLM-дайджестом: вместо «прочитайте eselect news read» отчёт содержит сам дайджест непрочитанных элементов.
- Отмена config-edit правок определяется видом действия механически: строки с аудит-маркером `# emerge-ai:` удаляются по маркеру; для command-exec — ссылка на бэкап/штатную отмену (`--noreplace` атома для deselect).

## Capabilities

### New Capabilities

- `repair-actions`: закрытый белый список исполняемых починок; род «белая команда» (emaint world check/fix с бэкапом, `emerge --deselect` с валидацией атома); отмена, идемпотентность, аудит каждого действия; ньюз-дайджест как read-only действие.

### Modified Capabilities

- `etc-update-llm`: новое требование «Обработка config file needs updating из план-фазы» — исполняемый вариант через существующий etcupdate-канал, интерактив только по согласию, неинтерактив — отметка в отчёте.

## Impact

- `src/emerge_ai/config_edit.py`: аудит-маркер удалений/отмены (`undo` для каждого kind), экспорт перечня kinds для меню.
- `src/emerge_ai/gate.py`/`cli.py`: новый род действия `white-command` в apply-канале (шаблон argv + валидаторы слотов + аудит + backup-hook перед исполнением).
- `src/emerge_ai/etcupdate.py`: точка входа «применить etcupdate по одному конкретному файлу» для план-фазы.
- `src/emerge_ai/agent.py`: новые инструменты/варианты: `emaint --check world` в песочнице; typed-спеки чинков для `plan-degraded` skeleton (emaint fix, deselect, etcupdate-file, news digest).
- Новый модуль `news.py` (eselect news list/read read-only + LLM-дайджест).
- После этого изменения report/`-p` и consent-диалог перестают печатать «не исполняемо» для находок живого кейса (edk2/yazi/world/config/env-lto).
- Порядок: зависит от `plan-degraded-triage` (находки — источник вариантов); независим от `consent-plan-dialogue` (варианты применимы и в существующем гейте, и в новом диалоге), полный эффект — после обоих.
