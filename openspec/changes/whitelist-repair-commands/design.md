# Design

## Context

Apply-канал (`gate.apply_variant` — единственная точка мутации) знает два механизма: правки `/etc/portage` (`config_edit.apply_package_edit`: use, accept_keywords, accept_license, mask, unmask, env — идемпотентный append) и оверлей-копии ebuild'ов. Песочница агента — только read-only инструменты. Требуется расширить пространство исполняемых починок, не размывая инварианты: argv от модели не принимается, emerge не подменяется (D1), consent/матрица/аудит обязательны, у всего есть отмена.

## Goals / Non-Goals

- Goals: род «белая команда» (emaint world fix/check, `emerge --deselect`); etcupdate по одному файлу из план-фазы; ньюз-дайджест; undo для каждого действия; валидация слотов до показа варианта и при исполнении.
- Non-Goals: произвольные команды; переписывание world из Python; автоматическая чистка (`--depclean`); синк репозитория; модификация файлов вне `/etc/portage` и world — кроме etcupdate-канала с его нативными бэкапами.

## Decisions

### D1. Белая команда = шаблон argv, а не Python-реализация

`CommandSpec{name, argv_template, slots[], backup?, undo}`; исполнение — subprocess настоящего бинарника (emaint, emerge) фиксированным argv. Для world-файла Python-реализация «починки» (парсинг/перезапись атомов) отвергнута: emaint --fix — эталонный алгоритм portage, своя копия гарантированно разъедётся с ним на bump'ах; копия-бэкап + чужой детерминированный алгоритм честнее для аудита.

### D2. Двойная валидация слотов

Валидаторы: членство атома в `@world` и содержимое vdb — через `portage_compat` (read-only Python API — его законная роль: контекст/проверки, не замена emerge); keyword-строки/CPV — regex формата. Первый проход — до рендера меню (не показываем протухший вариант), второй — внутри `apply_variant` (TOCTOU: параллельный прогон мог убрать атом; отказ до исполнения, вариант помечается неактуальным, оператору — сообщение, не исключение).

### D3. Undo — таблица, производная от вида действия

config-edit kinds: каждая добавленная строка получает аудит-комментарий `# emerge-ai:<run-id>`; отмена — удаление строк по маркеру (механическая идемпотентная правка). CommandSpec: `backup` (world — копия прогона) или `undo_text` (deselect — `emerge --noreplace <атом>`, зафиксирован в аудите). Текст отмены — обязательное поле consent-формулировки варианта (консистентно с раскрытием protect-контракта).

### D4. etcupdate: единичный файл, существующий LLM-разбор

Новая точка `etcupdate.apply_file(path, decision)`: решение «оставить/выбросить/смержить» — тот же промпт и источники документации, что у пост-сборочной ветки (etc-update-llm); бэкапы — нативные механизмы etcupdate. План-фазовая находка (`needs updating`) — отдельный от `etc_update_after_build` триггер: там политика пост-сборки, здесь явная находка в consent-диалоге.

### D5. Ньюз — данные, не команды

`eselect news list --predates` + `read <id>` — read-only subprocess, содержимое помечается недоверенным (скан prompt-injection существующий), дайджест строится тем же enrich-механизмом (тот же endpoint; без endpoint — список заголовков/дат). В отчёт попадает и в `-p`, и в мутационных ветках; действия по ньюзу (обновление затронутых пакетов) — обычные merge-сценарии, не отдельная команда.

### D6. Маппинг находка→шаблон в typed_variants

`typed_variants` (сейчас выводит фиксы из argv-атомов инцидента) перестраивается на findings-драйв: mask→`accept_keywords` exact-CPV; conflict→keyword/use-правка или deselect виновного атома; world-problems→`emaint --fix world`; needs-updating→etcupdate-файл. Модель выбирает/комментирует шаблоны, слоты берёт из находок (не из головы: CPV/атом — из доказательства находки).

## Risks / Trade-offs

- [`emaint --fix world` переписывает формат атомов] → копия прогона до; отмена = восстановить копию; аудит содержит diff-путём путь копии.
- [Deselect как «тихий» выход из конфликта маскирует проблему] → вариант не дефолтный, стоит после правок-кандидатов; deselect — advice.
- [Валидация по кэшированному world устаревает между рендером и выбором] → повторная валидация в apply (D2), отказ с объяснением.
- [News — недоверенный текст в промпте] → существующее сканирование инъекций + пометка «данные не команды»; ньюз не порождает исполняемых действий автоматически.
- [Двойная реализация «проверить мир» у агента и у пользователя] → инструмент агента и вариант меню исполняют одну и ту же белую команду — один путь.

## Migration Plan

Аддитивно; новых конфигов нет. Файлы-копии world живут рядом с world (имена видны в аудите). CHANGELOG: расширенный белый список действий.
