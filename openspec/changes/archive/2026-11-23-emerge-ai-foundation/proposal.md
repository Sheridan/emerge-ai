# Proposal

## Why

Штатный `emerge` регулярно срывается на блокировках, циклических зависимостях, USE-конфликтах, масках, сбоях fetch и ошибках сборки. Починка каждого такого сбоя требует знания внутренних механизмов portage и терпения, а необдуманное лечение способно сделать систему незагружаемой. `emerge-ai` — CLI-обёртка над `emerge` с LLM-агентом: штатный режим остаётся штатным emerge, а на сбоях агент диагностирует проблему, предлагает проверенные варианты починки с разбором последствий и применяет решение только с явного согласия пользователя, с гарантией «не сломать работающую систему» (risk-tiers + снапшоты/архивы).

## What Changes

- Новый CLI `emerge-ai`: полная passthrough-совместимость с флагами и кодами выхода `emerge`; версия проекта == версия portage, совместимость по `major.minor` (проект `3.0.x` с portage `3.0.*.*`), при несовпадении — сообщение и выход.
- Перехват `--pretend`/`--ask` и подобных: вывод emerge печатается штатно, после него обогащение (оценка времени сборки через genlop, дайджест грядущих изменений), финальный «Proceed?» задаёт emerge-ai.
- Собственные флаги: `--noninteractive` (fail-closed: агент лечит только rest-tier) и `--i-understand-what-i-am-doing-and-take-full-responsibility-for-consequences` (полная автономность агента, включая откат системы).
- LLM-агент на сбоях: классификация (блоки/циклы/маски/keywords/USE/лицензии/fetch/ошибки сборки и sandbox/config-protect), read-only цикл инструментов (чтение больших логов через grep/tail/sed, `emerge --pretend` для проверки гипотез, equery/portageq, поиск в журнале решений, web-доступ к документации), native tool-calling OpenAI-совместимого эндпоинта.
- Consent gate: N вариантов с анализом плюсов/минусов/рисков каждого; свой текст пользователя тоже проходит анализ последствий с повторным вопросом; цикл до подтверждения.
- Система доверия: 5 risk-tiers (boot / shell / сеть+ssh / GUI / остальные), классификацию определяет LLM с кэшированием.
- Откат: 1 btrfs-снапшот на запуск (только если в очереди есть tier 1–4) с удалением после успеха; при отсутствии снапшот-ФС — архив файлов устанавливаемой версии пакета (CONTENTS) и системного конфига.
- Лестница починки: правки `/etc/portage/package.*` (с аудит-комментариями) → user patches `/etc/portage/patches` → собственный оверлей emerge-ai (только когда без патча ebuild/исходников сборка невозможна; с реестром и предложением удаления после апстрим-фикса).
- etc-update через LLM: решение «оставить/выбросить/смержить» по документации пакета, подтверждение пользователем, атомарное применение по одному пакету.
- Журнал `/var/lib/emerge-ai/journal`: только подтверждённо-успешные решения; используется агентом при будущих сбоях.
- Автоматический doctor при сборке world/system: dry-run резолвера, риск-тирование, оценка времени.
- Дайджесты после завершения (опция конфига) и changelog-дайджест собранных пакетов (опция): локальные источники + release-changelog GitHub/аналогов + коммиты/мерджи git-репозиториев.
- Конфиг `/etc/portage/emerge-ai.json` (ключ API в конфиге, файлы 0600 root), промпты в `/usr/share/emerge-ai/prompts` и `/var/lib/emerge-ai/prompts`. Только systemd (openrc вне скоупа).

## Capabilities

### New Capabilities

- `cli-compat`: passthrough флагов и кодов выхода emerge, перехват pretend/ask, собственные флаги режимов, привязка версии к portage и проверка совместимости, systemd-only.
- `agent-loop-consent`: детекция и классификация сбоев, read-only цикл инструментов агента (включая верификацию гипотез через `emerge --pretend`), prompt-injection сканы, consent gate с анализом последствий и циклом «свой текст → разбор → повторный вопрос», матрица автономии по флагам, политика лимита токенов, журнал успешных решений и его поиск.
- `risk-tiers`: пятиуровневая классификация влияния пакетов (boot / shell / сеть+ssh / GUI / остальные) силами LLM с кэшем; влияние уровня на consent gate, снапшоты и автономность.
- `system-rollback`: btrfs-снапшот (один на запуск, только при наличии tier 1–4 в очереди, удаление после успеха) и fallback-архив файлов пакета и системного конфига; восстановление при откате.
- `overlay-patching`: лестница вмешательства (конфиг/use/маски с аудит-комментариями → user patches → оверлей emerge-ai), репозиторий emerge-ai с реестром и gc-предложениями.
- `etc-update-llm`: LLM-разбор защищённых конфигов (man/info//usr/share/web), подтверждение пользователем, атомарное применение по пакетам.
- `run-reporting`: enrich план-фазы (`-p`/`-a` + genlop-оценки + дайджест изменений), автоматический doctor на world/system, пост-запусковый дайджест и changelog собранных пакетов.
- `config-prompts`: схема и дефолты `/etc/portage/emerge-ai.json` (эндпоинт/ключ, язык=auto, рассуждения=вкл, web=вкл, дайджесты, etc-update), раскладка промптов, обязательность их исполнения, OpenAI-совместимый интерфейс с native tool-calling.

## Impact

- Новый пакет: `emerge-ai` версии 3.0.82.x, Python 3.14+, runtime-зависимость `=sys-apps/portage-3.0.*` (python-API portage read-only: depgraph, sets, метаданные, portageq, CONTENTS).
- Системные файлы: `/etc/portage/emerge-ai.json` (0600), `/usr/share/emerge-ai/prompts`, `/var/lib/emerge-ai/` (journal, prompts, overlay, кэш тиров), `/etc/portage/repos.conf/emerge-ai.conf`, `/etc/portage/patches`, btrfs-снапшоты.
- Внешние зависимости: OpenAI-совместимый LLM-эндпоинт (по умолчанию `http://127.0.0.1:8080/v1`, тесты только против него), web-доступ агента, genlop/equery/eix/git как read-only инструменты.
- Риски: недоверенный ввод (build.log, веб) при включённом web-доступе — смягчается read-only песочницей инструментов и consent gate; безопасность root-окружения — приоритет дизайна.
