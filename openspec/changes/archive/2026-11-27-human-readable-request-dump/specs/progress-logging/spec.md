# Spec Delta

## MODIFIED Requirements

### Requirement: Детальные логи при -v

При `-v`/`--verbose` (включая кластеры коротких опций) emerge-ai SHALL дополнительно печатать
в stderr тело каждого запроса к эндпоинту человекочитаемым блоком (см. «Человекочитаемый дамп
запроса»), а не сериализованным JSON, и длительность вызова. Блок SHALL печататься до
результата вызова, каждое усечение — отмечаться плашкой с исходным размером (отдельный кап
поля и кап блока). Флаг SHALL передаваться emerge без изменений. Без `-v` тело запроса SHALL
не печататься вовсе.

#### Scenario: Запрос показан

- **WHEN** выполнено `emerge-ai -av ...` с настроенным endpoint
- **THEN** перед результатом каждого LLM-вызова в stderr напечатан человекочитаемый блок
  запроса (при переполнении — с плашкой усечения), без ошибок и предупреждений

#### Scenario: Raw JSON в дампе отсутствует

- **WHEN** при `-v` напечатан дамп любого запроса
- **THEN** ни одна строка дампа не является сериализованным JSON-объектом или массивом и в
  тексте нет экранированных кавычек вида `\"`

#### Scenario: Усечение видно

- **WHEN** длинное поле сообщения или блок целиком превышают свой кап
- **THEN** усечённое место помечено плашкой с исходным числом символов, обрыв не выглядит
  как полный текст

#### Scenario: Без -v тел нет

- **WHEN** выполнено `emerge-ai -a ...` без `-v`
- **THEN** в stderr есть только короткие строки анонсов, дампов запросов нет

## ADDED Requirements

### Requirement: Человекочитаемый дамп запроса

Каждая строка дампа запроса SHALL идти в stderr с префиксом `emerge-ai: ` и SHALL описывать
содержимое словами: заголовок с параметрами вызова, затем по одному блоку на сообщение
(порядковый номер, роль, размер, превью текста), tool-call'ы ассистента — именем и
аргументами, результаты инструментов — отдельным блоком, инструменты — списком с описаниями.
Вложенные и неизвестные поля payload SHALL выводиться парами `key=value` с отступом; синтаксис
JSON в строках дампа не используется.

#### Scenario: Заголовок вызова

- **WHEN** при `-v` напечатан дамп запроса
- **THEN** первой строкой блока указаны модель, температура, число сообщений и число
  инструментов, а также общий размер тела запроса

#### Scenario: Сообщения по блоку

- **WHEN** запрос содержит системный промпт, пользовательский текст и историю
- **THEN** каждое сообщение занимает отдельную строку вида «№ · роль · N символов · превью»,
  многострочное содержимое свёрнуто в одну строку без потери признака объёма

#### Scenario: Tool-call виден командой

- **WHEN** в истории запроса есть ответ ассистента с tool-call'ами
- **THEN** каждый показан строкой с именем инструмента и его аргументами в виде `key=value`,
  без JSON-обёртки и без Base64/экранирования

#### Scenario: Результат инструмента свёрнут

- **WHEN** в запросе есть результат инструмента на тысячи символов
- **THEN** строка содержит имя инструмента (или идентификатор вызова), размер и превью
  начала, а не весь текст результата

#### Scenario: Инструменты перечислены

- **WHEN** запрос передаёт набор инструментов
- **THEN** после сообщений напечатан список инструментов по одной строке на инструмент: имя и
  описание (при длинном описании — с плашкой усечения)

#### Scenario: Неизвестное поле не превращается в JSON

- **WHEN** в payload появилось поле, не знакомое оформителю дампа (вложенный объект или массив)
- **THEN** оно показано парами `key=value` с отступом (для массива — с индексом элемента) и не
  печатается как сериализованный JSON

#### Scenario: Дамп не мешает окружению прогона

- **WHEN** stderr прогона с `-v` перенаправлен в файл (или задан `NO_COLOR`)
- **THEN** строки дампа полностью plain, без ANSI escape-кодов, stdout emerge и коды выхода
  не затронуты
