# Design

## Context

Язык ответов агента определяется в `Config.resolved_language()` (`src/emerge_ai/config.py:70-76`:
не-`auto` значение возвращается как есть — `ru`, `de`, …; `auto` резолвится по `LC_ALL`/`LANG`
в `russian`/`english`) и попадает только в prompt главного агента
(`prompts.collect_context` → `assemble_system_prompt`, `prompts.py:81-94`). Промпт LLM-сверки
конфигов языковую директиву не содержит вовсе: `ETC_SYSTEM` — англоязычная константа
(`etcupdate.py:66-72`), `build_merge_prompt` (`:75-89`) собирает user-часть с JSON-схемой,
`llm_decide` (`:106`) язык не принимает, CLI (`cli.py:180`) его не передаёт. Поэтому при
`language: ru` обоснования приходят по-английски (REVIEW_NOTES M12).

## Goals / Non-Goals

**Goals:** один источник языка для всех LLM-вызовов; обоснование (`reason`, текст цитат) —
на выбранном языке; безрисочный парсинг решения.

**Non-Goals:** перевод готовых ответов постобработкой, отдельные настройки языка для
etc-разбора, перевод `citations` (цитаты — дословные фрагменты источника).

## Decisions

**D1. Директива в system-части: `ETC_SYSTEM` → `etc_system(language)`.**
Функция возвращает тот же текст + `Always respond in {language}: write "reason" and any
explanatory text in {language}; keep JSON keys and action codes exactly as specified.`
Альтернатива — дописывать язык только в user-часть: отвергнуто, на длинные user-промпты с
двумя файлами и документацией model следует system-директиве стабильнее. Альтернатива —
post-hoc перевод вторым вызовом: отвергнуто, удваивает стоимость и искажает цитаты.

**D2. Язык — `cfg.resolved_language()`, значение передаётся как есть.**
Тот же источник, что у главного агента, поэтому коды (`de`) и имена (`russian`) одинаково
применимы — модель понимает и то, и другое (проверено главным агентом на `ru`/`auto`).
Альтернатива — таблица кодов→имён языков: отвергнута, дублирование без выигрыша.
Альтернатива — отдельный ключ `etc.language`: отвергнута, спецификация знает один язык ответов.

**D3. Язык — обязательный параметр, без значения по умолчанию.**
`build_merge_prompt(new, current, docs, language)` и
`llm_decide(client, newp, current, docs, language)`; CLI передаёт `cfg.resolved_language()`.
Альтернатива — `language="english"` по умолчанию: отвергнута, новый вызывающий код молча
вернётся к дефекту.

## Risks

- [Риск] Модель переведёт `action`/JSON-ключи и сломает `parse_decision` → митигация:
  явная оговорка в директиве («keep JSON keys and action codes exactly as specified»),
  тест с `language: de` и валидным ответом-двойником.
- [Риск] `language: de` даёт «de» в директиве, модель может ответить по-английски →
  митигация: поведение идентично главному агенту с тем же значением; при жалобах — таблица
  имён из D2 как отдельный будущий fix, контракт сценария не меняется.
- [Риск] Локализация `reason` ломает тесты, сверяющие текст → митигация: существующие
  тесты не завязаны на язык ответа, новый тест проверяет директиву в запросе, а не ответ.
