# Proposal

## Why

Требование базового спека «Исчерпание лимита токенов» (openspec/specs/
agent-loop-consent/spec.md:70-75) недостижимо: `finish_reason` из ответа
эндпоинта сохраняется в `Response` (src/emerge_ai/llm.py:26, 90), но нигде не
читается, а превышение лимита раундов инструментов — `LLMError`
(src/emerge_ai/llm.py:147) — глушится общим `except Exception` в `_maybe_agent`
до одной строки `agent unavailable` (src/emerge_ai/cli.py:140-142). Пользователь
не получает ни вопроса про продолжение, ни различимой записи в логе
(REVIEW_NOTES M13).

## What Changes

- Исчерпание лимита становится различимым сигналом: ответ с
  `finish_reason == "length"` и превышение раундов инструментария поднимают
  отдельный тип ошибки лимита (токены / раунды) вместо безымянного `LLMError`.
- В интерактивном запуске при исчерпании лимита оператору показывается явное
  сообщение и вопрос с тремя вариантами: продолжить разбор, свернуть разбор
  (уменьшить объём входных данных), завершить разбор. Выбор ждёт ввода — в
  соответствии с режимным каналом вопросов.
- «Продолжить» возобновляет разбор с увеличенным бюджетом раундов (не более
  одного продолжения на разбор), «свернуть» перезапускает разбор с укороченным
  окном лога и меньшим числом результатов инструментов.
- В неинтерактивном запуске вопроса нет: проблема записывается в журнал
  решений гейта (`decisions.log`) с указанием причины (tokens/rounds) и
  печатается развёрнутой строкой в stderr; прогон завершается штатно, код
  выхода emerge не скрывается.
- Прочие ошибки агента сохраняют нынешнее поведение (одна строка
  `agent unavailable`, код не меняется).

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `agent-loop-consent`: требование «Исчерпание лимита токенов» уточняется
  (различимость лимита от прочих ошибок, набор вариантов оператору, охват
  лимита раундов), добавляются недостижимые ранее сценарии.

## Impact

- Код: `src/emerge_ai/llm.py` (сигнал исчерпания), `src/emerge_ai/agent.py`
  (continued/narrowed разбор), `src/emerge_ai/cli.py` (`_maybe_agent` различает
  ошибку лимита), аудит через существующий `gate`-канал.
- Тесты: юниты на fake-клиент с `finish_reason="length"` и на переполнение
  раундов; интерактив/неинтерактив варианты; e2e без TTY.
- Документация: README — поведение при лимите.
- Смежные изменения: `wire-agent-apply-loop` трогает те же ветки сбоя — лимит
  внутри петли применения не должен запускать применение; landing после него.
