# Design

## Context

Вывод размазан по ~39 `print()` в семи модулях; единственный ANSI — безусловно-печатный dim для reasoning (`llm.py:95`). Захваченный вывод emerge хранится и подаётся в LLM/парсеры «как есть», поэтому ANSI-коды живого portage доходят до промптов и ломают регулярки `digest.py`. Жёсткие рамки: runtime — только stdlib (DECISIONS.md), вывод emerge в stdout — без изменений (spec `run-reporting`), тесты захватывают вывод через `capsys` (не-TTY). Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Единая точка решения «красить ли» и единая палитра; ни один `print` не принимает решение о цвете сам.
- Все три места показа LLM-текста проходят через один рендерер.
- Чистый от ANSI буфер захваченного вывода при неизменном passthrough.

**Non-Goals:**
- Интерактивный Q&A-канал агента (только маркер в тексте).
- Markdown-рендерер и markdown-sanitizer.
- Конфигурация палитры собственных сообщений (только LLM-блоки).
- Принудительная окраска в pipe.

## Decisions

### D1. Новый модуль `ui.py` вместо зависимости
Только stdlib запрещает `rich`/`colorama`. `ui.py`: SGR-константы, `supports_color(stream)` = `stream.isatty() and not os.environ.get("NO_COLOR") and os.environ.get("TERM") != "dumb"` (проверка при каждом вызове, не кэш импорта — тесты подменяют isatty), `paint(stream, sgr, text)` (plain, если цвета нет), `strip_ansi(text)`. Альтернатива — класс-эмиттер с маршрутизацией потоков: избыточно, call-site'ы сами выбирают stderr/stdout.

### D2. Хелперы формата, а не центральный emitter
Для собственных сообщений — тонкие функции (`ui.err/warn/ok/info`), возвращающие готовую строку с префиксом `emerge-ai: `; call-site оставляет `print(..., file=sys.stderr)`. Минимальная инвазия 39 точек, capsys-тесты видят plain и не ломаются. Фиксированная палитра: err=red, warn=yellow, ok=green, info=без акцента; подтверждение/bold; строки tier — градиент red→yellow→green→cyan→dim по `entry.tier`; diff `+`/`-` — green/red.

### D3. Рендерер LLM-блоков в `ui.py`
`ui.paint_llm_block(text, colors, stream)` — построчно: строки с префиксом `QUESTION:` получают question-цвет, остальное content-цвет; `reasoning` красится отдельно в `LLMClient.render` (там же уходит безусловно-печатный сегодня dim). Применяется в трёх точках: `LLMClient.render`, печать proposal в `cli._maybe_agent`, печать digest в `cli._changelog_mode`. `LLMClient` уже держит `cfg` — палитру читает из него; CLI-точки читают тот же `Config`.

### D4. Конфиг: `llm_colors` как вложенный dict с whitelist
`{"llm_colors": {"content": "cyan", "reasoning": "dim", "question": "yellow"}}`, значения — имена из фиксированного whitelist (16 базовых цветов + `dim`/`bold` + `off`/null), маппинг в SGR только из кода. Raw SGR/escape-строки не принимаются: конфиг не должен становиться каналом injection в терминал. Валидация в `Config.from_dict` через существующий `warn`-механизм: невалидное имя → warn + дефолт, остальная палитра сохраняется. Альтернатива — плоские ключи (`llm_color_content`): хуже масштабируется, отвергнуто.

### D5. ANSI-strip в точке захвата
`run_emerge_capturing` пишет в stdout сырые строки, а в возвращаемый буфер кладёт `strip_ansi(line)` — одно изменение чинит и `incident.stderr_tail`, и регулярки `digest.py`, и всё, что читает буфер (hooks выигрывают). Вывод emerge не меняется. Собственные subprocess-захваты `sandbox.py` (`journal_search`, `pretend_emerge`) стриппуются у источника — их вывод идёт только в LLM. `enrich.parse_genlop` уже стриппует — без изменений.

### D6. Промпт-директивы инлайном, не через rules-файлы
`PLAIN_TEXT`-директиву и конвенцию `QUESTION:` добавить в сборные системные промпты (`agent.propose`, `CHANGE_SYSTEM`), а не в `prompts/rules/*.md`: rules — упаковываемые данные (`/usr/share`), а директива — часть контракта вывода кода, её нужно видеть в тестах промптов.

## Risks / Trade-offs

- [Палитра `llm_colors` не переопределяет pipe→plain — пользователь может ждать обратного] → зафиксировано в спеке сценарием; warn не печатать, иначе шум.
- [Модель поставит markdown несмотря на директиву] → принято вариантом A: текст печатается как есть; при систематических нарушениях — вернуться к sanitizer отдельным change.
- [Ложные `QUESTION:`-строки в прозе] → безвредно: красится строка, содержимое не теряется.
- [Стрип ANSI в буфере изменит вход `hooks.run_hook`] → стрип только помогает парсерам; прогнать тесты hooks.
- [Capsys-тесты с `NO_COLOR` в окружении CI] → plain-вывод и есть ожидание тестов; цветные пути тестируются monkeypatch'ем isatty.
- [Proposal печатается дважды при `-v` (стриминг + финал)] → окраска обоих одинакова, дублирование — существующее поведение, не трогать в этом change.

## Migration Plan

Обычный релиз: новые опции конфига опциональны, дефолты сохраняют текущее поведение (кроме появления цвета в TTY и стрипа ANSI в буфере). Откат — удаление `ui.py` и откат точек; конфиг-ключи игнорируются со штатным warn про unknown keys.
