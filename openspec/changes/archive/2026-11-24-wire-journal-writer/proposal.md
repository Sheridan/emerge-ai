# Proposal

## Why

Писатель журнала решений не подключён: `journal.record`/`journal.finalize`
(src/emerge_ai/journal.py:41, 53) не вызываются ни из одного production-кода,
при этом `IncidentAgent` уже читает журнал для поиска прецедентов
(`journal.find`, src/emerge_ai/agent.py:399-406). Файл журнала не создаётся
никогда, поэтому поиск прецедента всегда промахивается и требование базового
спека «Журнал только успешных решений» недостижим (REVIEW_NOTES H4). Петля
применения, из которой журнал должен писаться, подключается смежным изменением
`wire-agent-apply-loop` — данное изменение идёт после него.

## What Changes

- После подтверждённого успеха (применённое фикс-действие + повтор исходного
  emerge завершился кодом 0) CLI записывает в журнал запись: отпечаток сбоя,
  класс, CPV, фрагмент контекста, применённое решение и список действий,
  способ подтверждения, `run_id`.
- Неудачные решения в журнал не попадают: запись происходит только через
  `finalize`, который отбраковывает неуспех (src/emerge_ai/journal.py:66-67).
- Идентификатор прогона (`run_id`), под которым запись попадает в журнал,
  передаётся в правки конфигов и в регистрацию overlay, которые уже принимают
  `journal_id` (src/emerge_ai/config_edit.py:23,
  src/emerge_ai/overlay.py:97), — аудит-комментарии связываются с журналом.
- Спецификационный путь журнала приводится к фактически используемому
  `/var/log/emerge-ai/journal.jsonl` (сейчас в спеке указан `/var/lib/...`).
- Недоступный или нечитаемый журнал не должен менять код выхода прогона.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `agent-loop-consent`: требование «Журнал только успешных решений»
  уточняется (путь, способ подтверждения успеха), добавляется требование про
  устойчивость к недоступному журналу.

## Impact

- Код: `src/emerge_ai/cli.py` (вызов `journal.finalize` в ветке успеха
  повторного merge), передача идентификатора записи в `config_edit`/`overlay`.
- Тесты: расширение `tests/test_journal.py` и e2e-прогон «сбой → фикс → успех
  → запись → повтор сбоя находит прецедент».
- Документация: README — раздел о журнале решений.
- Зависимости: требует завершённый `wire-agent-apply-loop` (петля, из которой
  берутся применённое действие, `run_id` и код повтора).
