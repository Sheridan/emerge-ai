# Design

## Context

В etc-flow два механизма подтверждения: единственный операторский промпт
«Apply LLM decision [Y/n/c=override action[:file]]» внутри `_etc_flow`
(`cli.py:188-196`, `input_fn` + `etcupdate.parse_override`) и keyword-гейт
`apply_decision(confirm_fn=...)` (`etcupdate.py`), без которого функция отказывается
мутировать (`applied: False, declined: True`). При подключении потока параметр
`confirm_fn` в `_etc_flow` добавили, но довязки до `apply_decision` не случилось —
`cli.py:196` захардкодил `lambda _p: True`. Итог (M6): параметр декоративен, а no-op
лямбда при чтении кода выглядит как дыра в подтверждении.

## Goals / Non-Goals

**Goals:** честная сигнатура `_etc_flow`, соответствующая поведению; ровно один
механизм согласия на файл; ноль изменений в пользовательском поведении.

**Non-Goals:** изменение семантики `apply_decision` (её `confirm_fn` — настоящий гейт,
используется прямыми тестами `tests/test_etcupdate.py:89,:92`); новый флаг
подтверждения на каждый файл; изменение текста промптов.

## Decisions

**D1. Удалить параметр, а не довязывать его.** Оба коллаута передают константы,
которые ничего не включают/выключают (`False` в `:320`, где поток с `llm=False`
выходит до решений; реальная `confirm` в `:421`), — значит поведение «подтверждение на
каждый файл» никому не нужно: поток сознательно делает один промпт с override.
Рассмотренная альтернатива — пробросить `confirm_fn` в `apply_decision`: добавила бы
молчаливый второй промпт поверх `input_fn` (или заставила бы менять семантику
коллаутов); отвергнута.

**D2. Сохранить no-op лямбду `apply_decision` с комментарием.** `confirm_fn` —
обязательный keyword `apply_decision`, ослаблять его (дефолт `lambda: True`) значит
снять единственную страховку прямой записи в файл. Однострочный комментарий в `:196`
объясняет, что согласие уже получено через `input_fn`/`parse_override`. Альтернатива —
увеличить `apply_decision` опциональным дефолтом: изменение публичной сигнатуры без
потребителя; отвергнута.

## Risks

- [Внешние вызывающие `_etc_flow`] → функция внутренняя (нет в README/specs/`__all__`);
  grep по репозиторию даёт только `cli.py:320,:421` и три теста в `test_etcupdate.py`.
- [При правке случайно удалить лямбду `:196` вместе с параметром] → задачи явно
  разделяют «удалить» и «оставить с комментарием»; если гейт откроется/закроется
  некорректно, тесты merge и override (`tests/test_etcupdate.py:135-162`) упадут.
