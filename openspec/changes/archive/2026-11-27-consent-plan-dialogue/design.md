# Design

## Context

Нынешний мутационный путь: protect создаётся молча (cli.py, до всяких вопросов), бинарный `Proceed?` — только при `-a`; интерактив без `-a` основан на фикции «TTY-запуск = согласие» (`_mutation_gate` docstring). Диалог расщеплён: `agent.ask_operator` (нумерованные варианты, free-text обратно модели, лимит 3) советует; `gate.gate()` (typed-варианты, `apply_variant`, аудит) исполняет, но free-text — тупик. Требуется сшить полуциклы, не вскрыв инварианты: единственная точка мутации, матрица автономности, аудит, «модель не поставляет команды» (D8), «точка до первого merge» (D2 system-rollback).

## Goals / Non-Goals

- Goals: один consent-диалог перед мутацией в интерактиве (plain и `-a`); все нумерованные варианты исполняемы; точка раскрыта до создания; свободный текст в контекст модели; раунды не ограничены; неинтерактив не тронут.
- Non-Goals: новые виды исполняемых действий (`whitelist-repair-commands`); изменение неинтерактивной матрицы/аудита; изменение поведения второго резолва при merge (кэширование плана — вне scope); live-детекция.

## Decisions

### D1. Финальный вопрос ведёт канал опроса агента, gate остаётся ядром исполнения

Consent-диалог — один вопрос, задаваемый через семантику `ask_operator`; в его options механически подмешиваются исполняемые typed-варианты; выбор номера исполняется существующим ядром (`autonomy_decision` → `apply_variant` → аудит). Свободный текст идёт модели в тот же контекст; она переспрашивает с пересобранными вариантами.
Альтернативы: отдельный цикл в cli без LLM (воспроизводит слепоту gate); доступ LLM к gate-опроснику (ломает детерминированное ядро D8).

### D2. Диалог работоспособен без LLM

Меню строится детерминированно: чистый план → `[merge] [abort]`; деградированный → typed-варианты из находок план-триажа + `[merge as-is]` + `[abort]` (cap 6, лишнее отсекается по конкретности — существующее правило ask_operator). LLM обогащает меню (комментарии, порядок, разбор free-text); без endpoint free-text даёт перезапуск меню с пометкой, что разбор недоступен. Диалог — механизм согласия, а не фича LLM.

### D3. Связка «текст пункта ↔ действие» механическая

Вариант рендерится из typed-спека (kind, цель, правка); модель оперирует ключами варианта (порядок, группировка, pros/cons-комментарии), но исполняемый пункт без typed-спека физически не имеет `action`. Ручных пунктов в меню нет: неисполнимый advice — строкой вне списка (инвариант отчёта plan-triage).

### D4. Protect после согласия, порядок без изменений: consent → protect → apply

D2 system-rollback («точка до первого merge») сохраняется: выбор исполняемого сценария = согласие, сразу за ним protect, затем действия сценария. Отказ/abort: ни точки, ни правок (сегодня protect до `Proceed?` — это и есть исправляемое поведение). Plain-интерактив начинает спрашивать — осознанный BREAKING (UX плотнее, ложных «y» меньше).

### D5. Раунды не ограничены; раздельные предохранители

`MAX_ASK_QUESTIONS` снимается: guard-и — abort в каждом раунде, EOF, ctrl-c; счётчик не печатается. Не путать с неснятыми лимитами технической петли: раунды tool-loop (`MAX_ROUNDS`/`MAX_TOOL_CALLS`), «conclude now» при исчерпании бюджета инструментов, 6-раундовая защита ядра gate от невалидного ввода (это парсер ввода, не диалог), `REPAIR_LIMIT` автономного post-merge цикла.

### D6. Итерация вместо комбинаторики

Варианты генерируются заново после каждого применения починки и ре-резолва (ландшафт находок меняется; первая починка может снять остальные находки). Комбинированный сценарий «починить всё применимое» законен: белосписочные правки идемпотентны («append if absent»), аудятся поштучно. Предвычислять 2^N сценариев не нужно.

### D7. `-a` и коды выхода

`-a`: меню заменяет `Proceed? [y/N]`; «merge as-is» ≡ прежний «y», abort ≡ «n» (тот же код выхода и семантика). `-a -p` — доминирование pretend, диалога нет (cli-compat не меняется). Неинтерактив: вопросов нет, protect автоматом, `_mutation_gate` как сейчас.

## Risks / Trade-offs

- [Экран согласия стал плотным: план + excluded + protect-блок + меню] → фиксированный формат из коротких строк; детали — под `-v`; пустой план не предлагает merge вообще.
- [Существование молчаливого protect в тестах/скриптах ломается (plain теперь ждёт ввод)] → в тестах stdin «y»; в CHANGELOG — BREAKING-заметка; CI неинтерактивен (не затронет).
- [Оператор кликает меню, не читая protect-блок] → блок — часть вопроса, не экран ниже; «y» без блока не существует в UI.
- [Расхождение плана показанного и второго резолва при merge] — как сегодня; блок честно называет пакеты excluded из показанного плана; кэш плана вне scope.
- [LLM-петля с переспросами при плохом endpoint] → free-text деградирует к детерминированному меню (D2), abort всегда доступен.

## Migration Plan

BREAKING UX (интерактивный plain теперь спрашивает) — в CHANGELOG следующего релиза. Данных не мигрируем; consent-блок читает существующие факты `rollback` (detect_root_fs, SNAP_BASE, USER_DATA_PREFIXES) без новых файлов.
