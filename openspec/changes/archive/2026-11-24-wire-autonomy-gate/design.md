# Design

## Context

Кириллический корень гейта готов: `autonomy_decision(mode, variant)` по флагам
режима возвращает AUTO/ASK/DENY с текстовым обоснованием
(src/emerge_ai/gate.py:48-71), `gate()` перед каждым `variant.action()` пишет
аудит-строку в `/var/log/emerge-ai/decisions.log` (gate.py:15, 73-136),
`tiers.noninteractive_auto_allowed` допускает к авторешению только rest-tier
(tiers.py:157-159). В cli ни один путь мутаций их не вызывает: обычная ветка
переходит к merge сразу (cli.py:309-311), ветка `-a` — сразу после `Proceed?`
или без вопроса в неинтерактиве (cli.py:361-368, 409-411). Рабочих согласия
сейчас два: интерактивный `Proceed?` и fail-closed на отсутствии точки
восстановления (cli.py:400-408). План с тирами вычисляется только в `-p`/`-a`
(фаза плана), обычный запуск плана не имеет.

## Goals / Non-Goals

- Goals: ни одна неинтерактивная мутация tiers 1–4 не проходит без решения
  матрицы и аудита; интерактивные согласия не ухудшаются; сообщения CLI
  соответствуют фактическим проверкам.
- Non-Goals: сам флаг `--i-understand-the-risks` (wire-risk-flag), гейт
  решений агента (wire-agent-apply-loop), план-фаза обычного запуска
  (plan-before-plain-merge), изменения матрицы gate.py.

## Decisions

- **D1. Seam `_mutation_gate(plan, mode)` перед `run_emerge_capturing`** в
  обеих ветках merge; решение берётся от максимального тира queued-пакетов
  плана и флагов режима, аудит — каналом гейта. Альтернатива — встраивать
  проверку в runner: runner обязан оставаться слепым исполнителем emerge.
- **D2. Обычный запуск без плана: консервативный фолбэк.** Пока общий план-путь
  не готов, неинтерактивный запуск без вычисленных тиров считает мутацию
  рискованной и останавливается с объяснением; интерактивный продолжается как
  сейчас (сам запуск команды оператором в TTY = согласие по semantics emerge).
  Альтернатива «пропускать без проверки» — именно та дыра, которую закрывает
  изменение.
- **D3. Аудит fail-closed в неинтерактиве.** AUTO без записи в журнал решений
  недействителен: нет аудита — нет мутации. В интерактиве сбой аудита —
  предупреждение, оператор уже согласился явно. Альтернатива fail-open:
  противоречит требованию наблюдаемости автоматных решений.
- **D4. Сообщение `-a`/неинтерактива печатается ПОСЛЕ гейта** и содержит его
  фактический вердикт и обоснование (gate.py уже его возвращает). Прежняя
  строка cli.py:361-368 удаляется. Альтернатива «оставить текст, добавить
  галочку проверки» оставляет ложь при сбое резолва.
- **D5. Код отказа = ненулевой, отличный от кодов emerge** (как `5` у отказа
  точки восстановления, cli.py:407), чтобы скрипты отличали остановку гейтом от
  сбоя сборки.

## Risks / Trade-offs

- [Неинтерактивные пайплайны (cron world-update) начнут падать на tier 1–4]
  → это и есть спека; выход — флаг ответственности или явный `-a` с оператором,
  сообщение гейта объясняет причину и путь обхода.
- [Двойной гейт с wire-agent-apply-loop на повторных merge] → повтор merge из
  петли проходит тот же seam; решение агента уже получило согласие, но аудит
  мутации остаётся — дубль аудита безвреден.
- [Максимальный тир плана консервативен: один критичный пакет блокирует весь
  merge] → соответствует базовой спеке («для tiers 1–4 — записывать проблему и
  завершаться»); декомпозиция планов — вне объёма.
