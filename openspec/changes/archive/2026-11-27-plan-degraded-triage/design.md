# Design

## Context

План-фаза (`cli.py`) завершается кодом 0 в большинстве бытовых поломок: `--keep-going` пропускает узлы, маски и конфликты — warnings, world-файл и config-файлы — тоже rc 0. Резольвер (`_incident_flow`) привязан к `rc != 0`, `build_incident` хранит только `stderr_tail[-4000:]`, дайджест (`enrich.py`) видит только распарсенный список плана. Требуется детектировать деградацию по самому выводу план-фазы, не ломая инварианты: emerge никогда не заменяется (D1), детерминированное ядро + LLM-надстройка (D8), модель не поставляет команды.

Ограничения среды: локальный endpoint с конечным контекстом (полный вывод `@world -av` — десятки…сотни KB, префилл дорог); вывод план-фазы уже проходит через построчные помпы `run_emerge_capturing` (ANSI-снятый буфер существует); sandbox-инструменты агента (`grep_log`, `read_file_window`) работают по путям прогона.

## Goals / Non-Goals

- Goals: вердикт «чисто/деградировано» без LLM и без второго резолва; полный текст — артефакт, в промпт — срез; advisory-отчёт в `-p`, отчёт в мутационных режимах; экономия — ноль новых LLM round-trip на чистом плане.
- Non-Goals: исполнение починок и расширение белого списка (`whitelist-repair-commands`); изменение вопросов/protect/merge (`consent-plan-dialogue`); live-детекция во время стриминга; structural-детекция через portage API.

## Decisions

### D1. Детектор — детерминированный severity-скан, не LLM-роутер

Каналы серьёзности portage (`!!!`, `WARNING:`, ` * IMPORTANT:`) плюс структурные блоки (`conflicts with`, `required by`, `masked by:`) плюс форменные флаги (`-u`/`-D`/`-N` при `Total: 0`). Ветвление потока определяет этот скан; LLM лишь обогащает.
Альтернатива — «весь вывод в LLM, модель решает чисто/нет»: отклонено, ложная «чистота» галлюцинацией дороже ложной деградации (детектор ошибается в безопасную сторону — лишний отчёт), плюс префилл 30–120k токенов на каждом чистом прогоне и слом без endpoint.

### D2. Компрессия, не диагноз: severity-срез

Срез = строки маркеров + N строк контекста окна + структурные блоки + строка итога; cap несколько KB, хвост — плашка «[capped, полный текст: <path>]». Реализуется как чистая функция по ANSI-снятому буферу (`triage.py`), вызывается на границе план-фазы (не в помпе — live-скан сознательно вне scope: стриминг остаётся байт-в-байт, тесты помпов не переписываются).
Альтернатива — регексп-классификатор проблем: отклонено, зоопарк паттернов молча пропускает незнакомые формулировки; здесь регексты отвечают только за релевантность, диагноз — за LLM/человеком.
Альтернатива — portage API (`backtrack_depgraph` in-process) ради типизированных причин skip: отклонено, второй полный резолв (~75s), расхождение с показанным на экране, хрупкость к внутренностям portage; API остаётся read-only контекстом для агента.

### D3. Один расширенный digest-вызов вместо отдельного триаж-вызова

`enrich.summarize_plan` получает `[severity-slice]` + дайджест; structured output расширяется полем `findings: [{kind, cpv|atom, evidence, line}]`; разбор через существующий `try_structured`, schema-failure → сводка отсутствует, находки детектора (строковые) всё равно печатаются.
Альтернатива — отдельный маленький вызов «только классификация»: лишний round-trip на каждом `-p`/`-a` прогоне ради данных, которые та же модель уже видит в этом же промпте.

### D4. Артефакт `plan-output.txt` в директории прогона

Пишется всегда при план-фазе (и при «чисто» — это источник для будущих разборов и тикетов). Инцидент нового класса `plan-degraded` несёт `log_path` на полный файл; `stderr_tail`-усечение для этого класса не применяется. `grep_log`/`read_file_window` получают этот путь в перечне доступных логов инцидента.
Альтернатива — слайсинг в памяти + чанки в промпт (map-reduce): сложнее, проигрывает файловому поиску по точности.

### D5. Отчёт: общий рендерер, разная глубина

`triage.render_report(verdict, findings, slice)` — один рендерер для `-p` и мутационных веток. В `-p` при деградации дополнительно запускается `IncidentAgent` (class `plan-degraded`, песочница `-p` = read-only, `ask_operator` нет — вопросы физически невозможны) для объяснений и candidate-строк; candidate-действия рендерятся из typed-спеков белосписочных видов, доступных прямо сейчас (`config_edit` kinds, etcupdate-канал); не-исполнимые починки печатаются отдельной строкой «система это пока не исполнит» (ожидание закрывает `whitelist-repair-commands`). Глубокий разбор — только при деградации: чистый `-p` не дорожает.
Альтернатива — всегда IncidentAgent при деградации и в мутационных режимах: десятки секунд до Proceed? без запроса оператора; в мутационных режимах полный разбор сделает изменение `consent-plan-dialogue` по явному выбору.

### D6. Совместимость вывода и кодов

stdout emerge печатается помпами без изменений до и во время план-фазы; отчёт — после дайджеста; коды выхода и `Proceed?`-семантика не меняются (изменение поведения «y» — вне scope). Deep-разбор в `-p` не зависит от интерактивности: он advisory и безвопросный, запускается только от вердикта «деградировано» и наличия endpoint; без endpoint печатается детерминированная часть отчёта. В мутационных режимах отчёт печатается и в неинтерактиве (он не действие).

## Risks / Trade-offs

- [Формулировка portage без маркеров не замечена] → fail-open к сегодняшнему поведению (Proceed? как есть); тесты на живых фикстурах, словарь маркеров расширяем в одном месте `triage.py`.
- [Ложный «degraded» (например, безобидный `IMPORTANT: news`)] → отчёт advisory, ни один поток не ветвится «в худшую» сторону; ветвление только на показ текста.
- [LLM-garbage в findings] → findings модели не управляют потоком; поток — за детерминированными маркер-находками.
- [cap съел доказательство] → полный файл доступен агенту; плашка капа указывает путь.
- [Двойная работа помпов/скана на гигантском выводе] → скан по уже готовому буферу O(n) regex, вне hot-пути стрима.

## Migration Plan

Аддитивно: новый модуль + расширение существующих вызовов; конфигурация не меняется; при удалении endpoint поведение деградирует к детерминированной части отчёта. Миграций данных нет; `plan-output.txt` — новый файл в существующей структуре директории прогона.
