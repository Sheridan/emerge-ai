# Design

## Context

- Ветка без `--pretend`/`--ask` (`cli.py:310-324`): `_advance_to_merge` → `run_emerge_capturing` → incident/агент/`_post_run_digest`; ни тиров, ни `rollback.protect`, ни doctor, ни plan_digest.
- План-ветка (`cli.py:326-357`): pretend-резолв (`333`), `plan_fn` c тированием (`349`), `plan_digest` в stdout (`352`), doctor при `is_mass_update` (`353-355`).
- protect живёт только в `ask`-ветке (`cli.py:376-395`), после «Proceed?» (`371`); cleanup точки — после успеха merge (`413-415`); abort при `prot.failed` + tier≤4 — `396-408` (exit 5).
- В обычном запуска интерактивный вопрос задаёт сам emerge штатным `[Yes/No]`; emerge-ai его не перехватывает (REVIEW_NOTES.md, H6).
- `run-reporting` «Enrich для pretend/ask» нормирует вывод план-фазы только для `-p`/`-a`; `console-output`/`cli-compat` требуют печатать вывод emerge без изменений.

## Goals / Non-Goals

**Goals**
- Один общий pre-merge блок для всех мутационных запусков: план → тиры → дайджест/doctor → protect; нарушение спеков `system-rollback`/`run-reporting` на обычном пути устранено.
- Штатный UX обычного запуска сохранён: никаких новых вопросов до merge, вывод emerge не испорчен.
- `-p` останавливается на плане; `-a` добавляет только свой «Proceed?».

**Non-Goals**
- Не объединять резолвы в один (это `avoid-double-resolve-in-plan`).
- Не менять содержимое дайджеста/doctor/protect-сообщений и код выхода.
- Не добавлять авто-откат после неудачного merge (`wire-rollback-channel`).

## Decisions

**D1. Единый pre-merge блок вместо дублирования protect в обычную ветку.** Порядок: `plan → digest/doctor → protect → (режимный confirm) → merge → cleanup/отчёт`. Все три режима (`-p`, `-a`, plain) идут через него; `-p` завершается после digest/doctor, plain — без своего confirm, `-a` — с «Proceed?». Альтернатива — точечно вызвать `protect`+`doctor` из обычной ветки — отвергнута: два места правки инварианта «точка до merge», разъезд логики при развитии.

**D2. protect ДО режимного подтверждения (для `-a` — до «Proceed?»).** Инвариант спека — точка существует перед первым merge; ставить её после вопроса значит держать окно, в котором прерванный по таймауту/EOF ввод уже пошёл в merge без защиты. Цена: при отказе («N»/Ctrl+C) точка создаётся зря → её надо убрать (D5). Альтернатива (protect после confirm, как сейчас в `-a`) оставляет окно и разносит порядок между ветками.

**D3. План-вывод на мутационном пути — в stderr.** В plain-запуске stdout до этого был чистым выводом emerge; дайджест/doctor/info protect пишутся в stderr, stdout остаётся passthrough вывода merge. В `-p`/`-a` план-фаза вывод остаётся как есть (stdout), он уже нормирован `run-reporting` и ожидаем интерактивным оператором. Альтернатива (stdout везде) ломает конвейеры вида `emerge-ai -uDN @world | tee` молча.

**D4. Сбой plan_fn/build_plan на мутационном пути не отключает защиту.** Если тиры неизвестны, «есть ли tier≤4» проверить нельзя, а спек требует защиты именно в этом случае — значит при недоступном плане точка создаётся безусловно (как для tier≤4); отказ создать точку при этом трактуется как `prot.failed` (abort/подтверждение, exit 5 — существующая механика `cli.py:396-408`). Альтернатива «warn и продолжить без защиты» молча воспроизводит H6.

**D5. Снятая/несостоявшаяся защита убирается.** Если merge не начался (отказ оператора, `rc` emerge = «отказ» при штатном `[Yes/No]`) или завершился с `prot.failed` и пустыми артефактами — созданная точка удаляется через `rollback.cleanup` с info-строкой; при INCIDENT точка сохраняется (готовность к откату, `wire-rollback-channel`).

## Risks / Trade-offs

- [Каждый мутационный запуск платит двойным резолвом (план-резолв + резолв самого emerge)] → время растёт линейно с world; задача `avoid-double-resolve-in-plan` делает план из одного резолва; для аварийного «быстро поставить пакет» это осознанная плата за recovery point.
- [Скрипты, парсившие stdout plain-запуска, видят новые строки] → все новые informational-блоки в stderr (D3); stdout побайтно прежний.
- [Поведение `-a`: точка теперь создаётся и при отказе «N»] → cleanup при отказе (D5), заметных следов не остаётся.
- [Рост диффа в cli.py задевает параллельные изменения (wire-rollback-channel, wire-autonomy-gate)] → pre-merge блок оформляется одной функцией-хелпером с явными параметрами режима; изменения-потребители добавляются в него, а не в ветки.
