# Design

## Context

`_etc_flow` (`src/emerge_ai/cli.py:145-197`) для каждого `*_etc-update-new*` файла обязан
собрать документацию и отдать её `etcupdate.llm_decide`. Веб-фаза `:172-178` определяет
замыкание `web(path)` с дефолтным аргументом `_sb=Sandbox()` (sandbox создаётся заново на
каждый файл), которое всегда тянет `https://wiki.gentoo.org/` — корневую страницу, не связанную
с файлом, — и читает несуществующий ключ `r["text"]`; `Sandbox.web_fetch` (`sandbox.py:125-141`)
отдаёт при успехе `{"url","content","truncated"}`, при ошибке `{"error",...}`, исключений не
бросает. `KeyError: 'text'` ловит широкий `except` `:181-183`, который печатает
«etc LLM unavailable» и `continue` — LLM не вызывается ни для одного файла; существующие
тесты (`tests/test_etcupdate.py:117`) ставят `web_access: false` и заглушку не выполняют.

## Goals / Non-Goals

**Goals:** реальный веб-контекст по пакету; детерминированный отказ «пустой список +
предупреждение»; неизменный контракт `docs: list[tuple[str, str]]` для
`collect_docs`/`llm_decide`.

**Non-Goals:** парсинг/суммаризация HTML, кэш страниц, man/info-источники (остаются на
совести prompt-правил), изменение формата решения LLM.

## Decisions

**D1. Загрузчик — `Sandbox.web_fetch`, вспомогательная функция в `cli.py`.**
`_pkg_docs(sandbox, path) -> list[tuple[str, str]]` рядом с `_etc_flow`; сам `Sandbox()`
создаётся один раз до цикла по файлам (сейчас — по объекту на файл в дефолтном аргументе
`:176`). В `try` веб-фаза больше не нужна — функция сама возвращает `[]`. Рассмотренная
альтернатива — новый модуль `websearch.py` с извлечением цитат: отвергнута, единственный
потребитель — `_etc_flow`, HTML-парсинг расширяет поверхность отказа.

**D2. Выбор URL — каталог пакетов при выводимой паре, иначе поиск по вики.**
Если последние компоненты пути дают `<cat>/<pn>` (путь под `package.use|package.accept_keywords|
package.mask|package.unmask`, обе части совпадают с регуляркой имени пакета) —
`https://packages.gentoo.org/packages/<cat>/<pn>` (первичный источник по брифу). Иначе —
`https://wiki.gentoo.org/index.php?search=<q>&fulltext=1`, где `q` — basename файла без
суффиксов `-rN`/`.pre-emerge-ai`/`_etc-update-new`. Альтернатива — всегда packages.gentoo.org:
отвергнута, из произвольного пути (`/etc/portage/make.conf`) пара `cat/pn` не восстанавливается.
Альтернатива — два запроса (каталог + wiki): отвергнута, лишний сетевой хвост на файл.

**D3. Ошибки → `[]` + предупреждение в stderr, не исключение.**
`web_fetch` может вернуть `{"error": ...}` или бросить исключение; оба случая печатают
`ui.warn("web docs unavailable for <q>: ...")` и дают `[]`; пустой/не-HTML ответ — тоже `[]`.
Альтернатива — пробрасывать в существующий `except` с `continue`: отвергнуто, это ровно
нынешний дефект (молчаливый пропуск файла).

**D4. Узкий `except` остаётся только вокруг `llm_decide`/`client_factory`.**
Веб-фаза выносится из-под него, чтобы сообщение `etc LLM unavailable` соответствовал тексту
ошибки (требование в дельте).

## Risks

- [Риск] HTML-страница каталога/wiki — шум в контексте LLM → митигация: `web_fetch` уже
  режет размер (`truncated`), промпт просит цитировать только релевантное; при «грязном» результате
  решение не хуже, чем без веб-контекста.
- [Риск] names в пути без категории дают плохой поисковый запрос → митигация: поиск по
  wiki по basename — штатный пользовательский путь, ошибки дешевы.
- [Риск] узкая регулярка имени пакета пропустит экзотические имена → митигация: fallback на
  wiki-поиск, а не отказ.
