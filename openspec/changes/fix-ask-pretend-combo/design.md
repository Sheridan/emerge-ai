# Design

## Context

- `cli.py:305-306` детектируют `pretend`/`ask` через `runner.flag_present` (учитывает кластеры: `-ap` считается и `-a`, и `-p`, `runner.py:74-83`).
- План-фаза (`cli.py:328-357`): для `ask` снимает `-a` (`330`), для чистого `-a` добавляет `--pretend` (`331-332`); при `-a -p` вывод уже pretend. Далее дайджест (`352`) и doctor (`353-355`).
- `ask`-ветка (`cli.py:361-425`) выполняется при любом `ask`, включая `-a -p`: «Proceed?» (`371`), затем `drop_flags(emerge_args, ASK_FLAGS + PRETEND_FLAGS)` (`375`) и реальный merge (`410`).
- Чистый `-p` выходит по `cli.py:427-428` с кодом 0 (ненулевой rc уже возвращён на `334-343`) — merge недостижим.
- Нативный emerge: `-a -p` не запускает merge (ask имеет смысл только для реального установочного прогона).

## Goals / Non-Goals

**Goals**
- Исключить запуск merge при любом активном pretend — совпадение с нативным emerge.
- Ровная семантика rc: `-a -p` = rc pretend-резолва.
- Минимальный диф: поведение `-a` (без `-p`) и `-p` (без `-a`) побайтно прежнее.

**Non-Goals**
- Не менять содержание «Proceed?» и ветку неинтерактивного autostart (`cli.py:362-370`) для чистого `-a`.
- Не трогать enrichment/doctor/protect — план-фаза остаётся как есть.
- Не вводить новых флагов.

## Decisions

**D1. Pretend доминирует над ask (решение пользователя).** Условие входа в `ask`-ветку merge получает отсечку: если `pretend` — сразу штатный выход план-фазы (`transition DONE`, `return rc`), без `confirm` и без `drop_flags`. Альтернатива — «спросить, но отвечать отказом» — отвергнута: вопрос без продолжения бессмысленен и расходится с emerge, который при `-a -p` вопроса не задаёт.

**D2. Точка отсечки — общий guard по `pretend` перед `if ask:` merge-блоком, а не правка `drop_flags`.** `drop_flags` (`runner.py:86-100`) семантически корректен (снять флаги для merge-аргументов) и используется для план-аргументов; ломать его ради одного вызова — риск для `-av`-кластеров. Альтернатива (кэшировать `merge_args` только при `not pretend` внутри блока) эквивалентна, но guard снаружи явно документирует инвариант «pretend ⇒ нет merge».

**D3. rc = rc план-фазы.** При `-a -p` резолв уже выполнен один раз (`333`), его rc и есть результат; отдельный rc для «отменённого merge» не вводится — emerge-ai возвращает коды emerge (спека «Passthrough флагов emerge»).

## Risks / Trade-offs

- [Скрипты, зависевшие от «`-a -p` ⇒ merge после y»] → **BREAKING** зафиксирован в proposal; README обновляется, в выводе при `-a -p` появляется info-строка «pretend: merge skipped» — смена поведения видна глазами.
- [Расхождение с `run-reporting` «Ask с подтверждением»] → сценарий спека — `-a @world` без `-p`, он не затронут; новый сценарий `-a -p` добавлен в cli-compat и противоречия не создаёт.
- [Кластер `-ap`] → покрыт `flag_present`/кластерной логикой (`runner.py:74-83`), отдельный тест в задачах.
