# Design

## Context

- `rollback.rollback(run_id, *, confirm_fn, btrfs_fn=, tar_fn=)` (`rollback.py:135-166`) — готовый защищённый канал: разбор → «Refusing» при отказе → «Restored from snapshot» (онлайн) или инструкция + «Snapshot retained» (офлайн). Ноль вызовов из CLI.
- `Protection.run_id` — `emerge-ai-<unix_ts>`; артефакты: снапшоты `/.snapshots/emerge-ai/<run_id>`, архив `/var/lib/emerge-ai/archives/<run_id>`. Единственный источник идентификатора — память процесса: после завершения запуска точки «немами» (ни manifest, ни списка).
- `cleanup()` удаляет артефакты только после успеха merge; после INCIDENT точка сохраняется (`cleanup_run_artifacts` в cli) — кандидат на откат есть, предложить некому.
- Флаг ответственности уже в реестре собственных флагов (`flags.py` — `OWN_FLAGS`, `--i-understand-...`), матрица автономии и `confirm_fn`-механика exist; `mount_root_rw`/`start_openrc_service` в runner — строительные блоки офлайн-исполнения.
- README (§«Восстановление», README.md:147-159) уже обещает канал и ссылается на несуществующий флаг.

## Goals / Non-Goals

**Goals**
- Канал достижим: (а) после неудачного merge с tier≤4 в интерактиве/с флагом; (б) режимом `--rollback` в любой момент.
- Офлайн-ветка (`rollback.py` instructions) перестаёт быть мёртвой; артефакты не удаляются молча.
- Разделение ответственности не меняется: автономный откат — только с флагом ответственности.

**Non-Goals**
- Не делать авто-откат без явного решения (ни после merge, ни из `--rollback`).
- Не реализовать онлайн-восстановление root-подтома — только инструкция (по спеку).
- Не менять механику создания точек/архивов и правила cleanup.

## Decisions

**D1. Реестр точек: manifest.json рядом с артефактами + обход каталогов как fallback.** `protect` пишет `/.snapshots/emerge-ai/manifest.json` (run_id, таймстемп, план/пакеты, tier, тип артефакта, rc последнего запуска по возможности); `list_protections()` читает manifest, при его отсутствии/рассинхроне — union по каталогам `SNAP_BASE`/`ARCHIVE_BASE`. Альтернатива (только обход каталогов) не даёт метаданных для разбора последствий («что было в очереди»); альтернатива (state-файл в стейт-директории отдельно) расходится с местом артефактов при `--state-dir`.

**D2. `--rollback` — собственный флаг-режим, argv целиком его.** При наличии `--rollback` emerge не запускается вообще (позиционные атомы — не пакеты, а фильтр не нужен); режим: `list_protections()` → таблица (run_id, дата, пакеты, тип) → выбор (в неинтерактиве — единственный/последний или аргумент-фильтр не заводим, v1: интерактивный выбор либо `RC=5`-подсказка) → `rollback.rollback(confirm_fn=confirm)`. `--noninteractive` без флага ответственности — отказ с инструкцией (fail-closed, как вся матрица). Альтернатива (подкоманда `emerge-ai rollback`) ломает принцип «argv — флаги emerge + собственные» из cli-compat.

**D3. Post-merge hook в обработчике неудачного merge (единая точка для всех режимов).** Условие показа предложения: mqueue содержал tier≤4, есть сохранённая точка, merge завершился неудачей (включая INCIDENT). Реакция: флаг ответственности → авто-rollback (`confirm_fn` = always-yes, логирование) — по базовому правилу «автономия только с флагом»; TTY → `confirm` с последствиями (что вернётся: конфиги, /var/lib/world, список пакетов очереди); не-TTY без флага → warn + строка-подсказка `emerge-ai --rollback`. Состояние «merge отменён оператором / нечего откатывать» — не предложение, а штатный путь. Альтернатива (только `--rollback`, без предложения) оставила бы спековую формулировку «emerge-ai SHALL предложить» неудовлетворённой.

**D4. Офлайн-случай: тот же `rollback.rollback`, исполнение — инструкцией, плюс опция `--apply-instructions` не заводим.** Ветка root-подтома возвращает текстовые шаги (umount/mount -o remount,rw, btrfs subvolume delete/create или tar -x, рестарт svc); CLI печатает их как есть и явно говорит, что система НЕ изменена. Автономное офлайн-исполнение — сознательно нет: remount корня живым процессом за пределами теста.

**D5. README: исправить имя флага (README.md:159 → реальный `--i-understand-what-i-am-doing-and-take-full-responsibility-for-consequences`), добавить `--rollback` в таблицу собственных флагов (§3/§7).**

## Risks / Trade-offs

- [Откат после INCIDENT может замаскировать проблему, которую оператор хотел разобрать] → предложение, а не действие; «Refusing to roll back» — штатный ответ; при неинтерактиве без флага вообще ничего не восстанавливается.
- [Manifest рассинхронизируется с диском (ручное удаление каталогов)] → обход каталогов как fallback (D1), в таблице помечается «manifest отсутствует/лишний»; операции идут по фактическим артефактам.
- [`--rollback` интерактивен, в CI бесполезен] → сознано: автономный откат требует флаг ответственности (спец), в CI подсказка — путь «восстанови руками по инструкции».
- [Пересечение с `wire-autonomy-gate` (матрица автономии для откатов ещё не написана)] → хук использует существующий `confirm`/флаг ответственности; при переносе решений в матрицу хук становится одним из её вызывающих.
