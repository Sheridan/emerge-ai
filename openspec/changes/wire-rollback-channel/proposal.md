# Proposal

## Why

Канал отката реализован, но не выведен наружу: `rollback.rollback()` (разбор последствий → подтверждение → восстановление, `rollback.py:135-166`) не вызывается ниоткуда в CLI — доступны только `protect` (`cli.py:77-80`) и `cleanup` (`cli.py:413-415`) (замечание H3, REVIEW_NOTES.md:45-52). Спек `system-rollback` «Откат по решению пользователя» (spec:37-42) требует предложения отката после неудачной установки критичного пакета, а «Недоступный онлайн-откат» (spec:44-49) — сохранения снапшота и пошаговой инструкции; ветка инструкций (`rollback.py:141-166`) мертва. README §«Восстановление (rollback)» (README.md:147-159) уже описывает канал как работающий: снапшоты/архивы создаются, но штатно восстановить систему нельзя — только руками.

## What Changes

- Собственный флаг `--rollback` (точныйmatch, любая позиция argv, по общему механизму собственных флагов): режим восстановления — список доступных точек восстановления, разбор последствий, подтверждение, исполнение; emerge в этом режиме не запускается.
- Предложение отката внутри запуска: после неудачного merge очереди tier≤4 с сохранённой точкой — в интерактиве вопрос с разбором последствий, при флаге ответственности — автономное исполнение, в неинтерактиве без флага — лог и подсказка про `--rollback`.
- Оживает ветка «недоступный онлайн-откат»: root-подтом/требующие перезагрузки случаи печатают инструкцию и сохраняют артефакты (никогда не удаляются молча).
- README: исправить несуществующее имя `--i-understand-the-risks` (README.md:159) на реальный флаг, описать `--rollback`.

### Modified Capabilities

- `system-rollback`: «Откат по решению пользователя» — канал достижим из CLI (режим `--rollback`, предложение после неудачного merge); «Недоступный онлайн-откат» — инструкция и сохранение артефактов как часть того же достижимого канала. Базовые тексты требований верны, не хватало нормативной достижимости. `cli-compat` не трогаем: `--rollback` — очередной собственный флаг по уже нормированному правилу «Собственные флаги emerge-ai».

## Impact

- `src/emerge_ai/flags.py` — `--rollback` в реестр собственных флагов (подсказка в `OWN_FLAG_HELP` подтянется автоматически).
- `src/emerge_ai/cli.py` — режим восстановления + предложение отката после инцидента merge.
- `src/emerge_ai/rollback.py` — перечисление точек восстановления по журналу запусков и диску; исполнимый executor для онлайн-случая (архив).
- `tests/test_rollback.py`, `tests/test_cli.py` — режим и предложение после merge.
- `README.md` — §«Восстановление (rollback)».
- Зависимости: после `plan-before-plain-merge` (общий мутационный путь даёт точки восстановления обычным запускам и единое место для post-merge hook).
