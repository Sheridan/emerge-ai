# Design

## Context

Мотивация — в proposal.md (Why); здесь — состояние канала, из которого следует
подход.

- `config_edit.apply_package_edit(kind, ...)` и появившиеся в соседнем change
  `resolve_package_target`/`destination_label` строят имя как
  `f"package.{kind}"`. Это предположение верно для пяти видов из шести и
  неверно для `accept_license`.
- Имя вида — часть лексики, а не путь: оно в `KINDS`, в ключах
  `UNDO_TABLE`, в подсказке лестницы для модели
  (`prompts/rules/20-ladder.md`: «keywords/masks/use/accept_license») и в
  заголовках вариантов. Продюсеров вида нет (`agent.typed_variants` порождает
  `unmask`, `consent.menu_specs` — `accept_keywords`), то есть ломать нечего.
- Portage читает лицензии из `package.license` (`LicenseManager.py`), переменная
  при этом называется `ACCEPT_LICENSE` — отсюда расхождение. Для keyword'ов
  расхождения нет (`package.accept_keywords` ← `ACCEPT_KEYWORDS`), поэтому
  правило «имя файла = имя вида» нельзя ни «починить» переименованием вида, ни
  сохранить как инвариант.
- `package_files(kind=None)` обходит `glob("package.*")`, то есть уже сегодня
  видит `package.license` и (если он у кого-то создан вручную)
  `package.accept_license` — обзор и отмена по аудит-маркеру работают с любым
  именем, разрешение цели нужно только для записи.
- Сообщение о пропуске дубля в `cli._apply_action` печатает
  `package.{action['kind']}` — оно тоже обязано называть имя канала, иначе
  «already present» ссылается на файл, которого правка не касается.

## Goals / Non-Goals

**Goals:**

- Одно место переводит «вид → имя файла», и оно же питает запись, показ,
  отмену, обзор и текст отмены.
- Канал физически не способен создать файл, который portage не читает.
- Дрейф имени ловится тестом, а не ревью.

**Non-Goals:**

- Не переименовываем виды и не меняем ключи действий/вариантов.
- Не мигрируем и не удаляем уже существующие `package.accept_license`
  (продюсера не было; при ручном существовании файл остаётся в обзоре и в
  отмене по маркеру, потому что обход идёт по `package.*`).
- Не добавляем новые виды правок и не поддерживаем `package.provided`,
  `package.keywords` и new-style `packages.*`.

## Decisions

### D1. Таблица «вид → имя файла» вместо частного случая в разрешении цели

`config_edit.CHANNEL_FILE = {"accept_license": "package.license"}` и
`channel_file(kind) -> str` (иначе `f"package.{kind}"`). Все четыре места —
`resolve_package_target`, `destination_label`, `UNDO_TABLE`, `package_files` —
берут имя из неё. Альтернатива `if kind == "accept_license"` внутри
`resolve_package_target`: отвергнуто, потому что тогда имя канала расходится с
`UNDO_TABLE` и с сообщением cli — ровно тот класс дефекта, который чинится.

### D2. Имя вида остаётся `accept_license`

Переименование вида в `license` (тогда `package.<kind>` совпало бы с файлом)
отвергнуто: имя вида — словарь инцидентов и лестницы (`incident.py`
классифицирует `license`, `ladder.CLASS_FLOOR["license"] = "package-edit"`,
подсказка модели говорит `accept_license`), и оно уже в текстах отмены; ради
экономии одной таблицы менять лексику LLM-канала и ключи аудитов — значит
чинить невидимый для пользователя дефект ценой изменения внешнего словаря
проекта. Разделение «имя вида ↔ имя файла» — и есть то, что фиксирует
различие двух независимых словарей portage.

### D3. Каталог лицензий подчиняется раскладке из соседнего change без исключений

`resolve_package_target("accept_license", line, etc_dir)` после D1 работает с
`package.license` как с любым другим именем: каталог → файл категории по
категории атома, резерв `package.license/aimerge`, недоступная цель →
`ChannelError`. Исключений в коде разрешения не появляется — проверка юнитом на
tmp-корне с каталогом `package.license`.

### D4. Тест-инвариант имени, а не сверка с portage

В `tests/test_config_edit.py` фиксируется ожидаемое отображение всех видов
буквально (`{"use": "package.use", ..., "accept_license": "package.license"}`) и
отдельно — что множество имён ⊆ перечня читаемых portage имён (тот же список
константой). Считывать имена из `portage` (например из `LicenseManager`)
отвергнуто: канал не должен импортировать portage ради чистой работы с файловой
системой (аргумент повторён за `fix-package-edit-directory-target` D2), и
тест, сверяющийся с тем же источником, что и код, ничего не проверяет.

### D5. Сообщения и подсказка называют файл

`cli._apply_action` печатает `f"{config_edit.channel_file(kind)}: '…' already
present"`; в `prompts/rules/20-ladder.md` у уровня 1 добавляется имя файла
лицензий, чтобы совет модели не ссылался на `package.accept_license`. Текст
подсказки ни один тест не закрепляет; это единственная правка LLM-канала.

## Risks / Trade-offs

- [Новый вид добавлен без записи в `CHANNEL_FILE`] → `channel_file` даст
  `package.<kind>`; тест-инвариант из D4 падает на виде, имя которого не в
  читаемом перечне, — дрейф виден сразу в CI.
- [`package.license` — каталог у пользователя, а `package.accept_license` уже
  создан вручную с его строками] → канал пишет только в `package.license`;
  чужой файл не читается для записи и не трогается, но остаётся видимым в
  обзоре (`package.*`) и чистится отменой, если в нём есть строки с нашим
  маркером. Никакой автоматической миграции не делается намеренно.
- [Разошедшиеся имена в документации и в таблице] → README (раздел про канал
  правки) и `LIVE_CHECKS.md` перечисляют имена в том же виде; живая проверка
  требует `test ! -e /etc/portage/package.accept_license`.
- [Порядок относительно `fix-package-edit-directory-target`] → правка опирается
  на `resolve_package_target`/`package_files`; до их появления применять её
  нельзя, и наоборот она не меняет их контракт — только имя, которое они
  разрешают.

## Migration Plan

Аддитивно, без конфигов и миграций: на файловых раскладках меняется только
адресат правок лицензий (продюсеров которых нет), на каталожных — то же самое
внутри каталога. Откат change — revert: `package.accept_license` возвращается
как имя канала, поведение остальных видов не затронуто.
