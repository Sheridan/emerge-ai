# Design

## Context

- `config_edit.py` (68 строк): `audit_comment` (формат `# emerge-ai: <дата> <journal_id> <reason>`), `apply_package_edit` (безусловный append строки `<line> <аудит-комментарий>` в `package.<kind>`, mkdir родителей), `get_package_edit_lines` (пары `(строка, is_audit)`; распознаёт отдельный комментарий по `COMMENT_RE` и inline-вхождение `# emerge-ai:`), `apply_user_patch` (заголовок + текст в `<patches>/<cat>/<pn>/<name>.diff`, перезапись). Дефолтные корни — реальный `/etc/portage` (`config_edit.py:26,37,59`).
- Покрытие сегодня: `test_ladder.py:30-49` — smoke на аудит-комментарий и размещение патча; L3 (REVIEW_NOTES.md:196-200) фиксирует отсутствие тестов канала в целом; модуль в CLI не подключён (H5).
- `-a -p`: ни один CLI-тест не прогоняет эту связку; `fix-ask-pretend-combo` зафиксировал семантику — план-фаза отрабатывает, merge не запускается, «Proceed?» не предлагается, rc = rc плана (spec cli-compat «Доминирование --pretend над --ask», сценарии «Связка -a -p не устанавливает», «Кластер -ap»).
- Рабочие паттерны тестов: stub-emerge со списком вызовов и инъекция `plan_fn` (`test_cli.py:53-124`), фикстура `TODAY` и `tmp_path` для config_edit (`test_ladder.py:9,24-48`).

## Goals / Non-Goals

**Goals**
- Контракт канала записи (формат аудита, append без дедупа, область записи, разбор строк) закреплён тестами — до подключения лестницы к CLI (H5).
- Семантика `-a -p`/`-ap` закреплена CLI-тестами по final-спику; regression против возврата к «merge после плана».
- Тесты физически не способны тронуть настоящий `/etc/portage`.

**Non-Goals**
- Не менять `src/` ни на строку; найденные сверх контракта дефекты — отдельное изменение.
- Не добавлять дедуп/идемпотентность в `apply_package_edit` (тесты фиксируют текущее поведение).
- Не рефакторить `test_ladder.py` и не переносить его два smoke-теста.

## Decisions

**D1. Новый модуль `tests/test_config_edit.py`, существующие smoke-тесты не трогаем.** Тематический модуль проще находить и расширять при подключении H5; перенос тестов из `test_ladder.py` создал бы лишние пересечения с изменениями, правящими этот файл. Альтернатива (расширить test_ladder) отвергнута: модуль про выбор уровня лестницы, а не про канал записи.

**D2. Тесты фиксируют текущий контракт, а не желаемый.** Два одинаковых `apply_package_edit` → две строки в файле (append без дедупа) — тестируется и комментируется как зафиксированное поведение, а не как эталон. Альтернатива (тест на дедуп) отвергнута: он красный, а src менять запрещено скоупом изменения.

**D3. Все вызовы — с явным tmp-корнём; ни одного вызова с дефолтными параметрами.** Каждый тест передаёт `etc_dir`/`patches_dir=tmp_path/...` и дополнительно проверяет, что вне корня файлов не появилось. Автофикстура, подменяющая дефолты, отвергнута: магическая глобальная подмена маскирует ошибки передачи параметров.

**D4. CLI-тесты `-a -p` строятся на существующих stub-паттернах и final-семантике.**Stub-emerge пишет аргументы каждого прогона в журнал; утверждения: ровно один прогон и в нём `--pretend`; ни stdout, ни stderr не содержат «Proceed?» (stdin — monkeypatched `input`/read с падением при обращении); rc совпадает с rc план-фазы — отдельно успех (0) и провал плана (rc emerge ≠ 0, `incident class=plan-failed` в persisted-run). Кластер `-ap` — тот же тест парой строк. Опираться на спеку `fix-ask-pretend-combo`, а не на текущий код: изменение применяется после него. Альтернатива (писать тесты под нынешнее поведение) отвергнута: закрепила бы баг H1.

## Risks / Trade-offs

- [Fix-ask-pretend-combo сдвинет детали (формулировки, rc) → тесты покраснеют] → тесты выводят утверждения из сценариев спека (именованные сценарии в комментариях тестов), а не из приватных деталей кода.
- [Фиксация append-без-дедупа легитимизирует шум в package.use] → комментарий в тесте + отсылка к L3/H5: канал не подключён к CLI, контракт изменится вместе с подключением.
- [Хрупкость формата аудит-строки (дата, `journal_id` пустой → `-`)] → фиксированная `now=` (паттерн `TODAY`), отдельные тесты на пустой journal_id.
- [Тесты «stdin не читается» зависят от способа чтения confirm] → использовать тот же канал, что и существующие quiet-тесты (`-av` non-tty покрыт), — общий helper при необходимости.
