# Proposal

## Why

README обещает, что после дословного вывода `-p`/`-a` «emerge-ai добавляет LLM-обогащение плана» (`README.md:66-67`), и спек run-reporting требует «добавить обогащение от LLM» (`openspec/specs/run-reporting/spec.md:9`). Фактически в план-фазе печатается `plan_digest` — чисто детерминированный текст: tier-распределение и genlop-оценка (`src/emerge_ai/enrich.py:47-72`, вызов `src/emerge_ai/cli.py:352`); LLM в разборе плана не участвует вообще (REVIEW_NOTES M4, `REVIEW_NOTES.md:116-121`). Это расхождение обещания и поведения, а не только документации: пользователь читает «дайджест грядущих изменений» и получает механический список. Решение — добавить настоящий LLM-компонент: сводку «что важно в этом плане» поверх детерминированного дайджеста, а не переписывать README в сторону уменьшения.

## What Changes

- `plan_digest` получает необязательный LLM-seam: при настроенном endpoint после детерминированных строк (tier-распределение, genlop-оценка — без изменений) печатается LLM-сводка плана (2–5 строк plain text, через `ui.paint_llm_block`).
- Детерминированное ядро остаётся источником всех чисел: LLM интерпретирует, но не порождает оценки времени и tier — числа в LLM-тексте не нормируются и не заменяют ядро.
- Деградация без LLM — штатный режим: при отсутствии endpoint (`cfg.endpoint` пуст) или ошибке/таймауте клиента печатается только детерминированный дайджест, без LLM-блока и без новых warn-строк (план-фаза и так живёт под «enrichment must never break emerge's own flow», `cli.py:346-357`).
- Данные плана уходят в промпт через `injection.wrap_untrusted` (CPV — контент из чужих эбилдов), ответ рендерится plain text директивой, как прочие LLM-блоки.
- Финальный вопрос «Proceed?» и его позиция не меняются; `run_emerge_capturing` и вывод emerge — без изменений.

### Modified Capabilities

- `run-reporting`: требование «Enrich для pretend/ask» уточняется — обогащение состоит из детерминированного ядра и LLM-сводки; фиксируется деградация до ядра без LLM.

## Impact

- `src/emerge_ai/enrich.py`: `plan_digest` — необязательный параметр LLM-колбэка, сборка промпта, вывод сводки через `ui.paint_llm_block`.
- `src/emerge_ai/cli.py`: план-фаза (`cli.py:346-352`) — конструирование клиента при наличии endpoint (паттерн уже есть в `_changelog_mode`, `cli.py:238-250`); отказ LLM не должен глотать всё обогащение внешним except (`cli.py:356-357`) — см. design D3.
- `README.md:66-67` — обещание становится истинным без правки текста; `REVIEW_NOTES.md` M4 закрывается.
- `tests/test_enrich.py`/`tests/test_cli_integration.py`: фейковый LLM-колбэк (инъекция вместо `ScriptedClient`), тесты деградации; stable-вывод детерминированного ядра не меняется.
