# Design

## Context

- `plan_digest` (`enrich.py:47-72`) принимает `plan` и `estimate=genlop_estimate`, печатает tier-строки (с фиксированным градиентом риска) и суммарную оценку; LLM не видит.
- Вызов — `cli.py:352` внутри `try/except Exception` («enrichment must never break emerge's own flow», `cli.py:346-357`): любое падение обогащения уже сводится к warn-строке в stderr.
- Паттерн «LLM при наличии endpoint» в проекте есть: `_changelog_mode` (`cli.py:238-250`) и `_make_tier_service` — конфиг `endpoint`/`model`/`timeout` (`config.py:15-27`).
- Рендер LLM-блоков унифицирован: `ui.paint_llm_block` (`ui.py:118-121`), plain text директива — `prompts.PLAIN_TEXT_DIRECTIVE` (`prompts.py:16`), защита чужого текста — `injection.wrap_untrusted`.

## Goals / Non-Goals

**Goals:**
- Настоящий LLM-блок в enrich фазы плана: сводка «что важно в этом плане» после детерминированных строк.
- Числа (tier, оценки, состав) по-прежнему только из детерминированного ядра; LLM не может сорвать план-фазу.
- Поведение без endpoint не отличается от сегодняшнего — никаких новых warn-ов.

**Non-Goals:**
- Пересчёт tier/оценок LLM, изменения risk-tiers и genlop.
- Кэш сводок между запусками; стриминг токенов (блок печатается целиком).
- Изменение ветки `-a`-подтверждения и `run_emerge_capturing`.

## Decisions

### D1: seam — инъектируемый колбэк, а не конструирование клиента внутри enrich
`plan_digest(plan, estimate=..., stream=None, summarize=None)`: `summarize(digest_text) -> str | None` — вызывающий (cli) замыкает LLMClient, enrich остаётся чистым и тестируемым без сети. Альтернатива — передавать `cfg`/client напрямую в enrich: связывает модуль с сетевым слоем, мешает unit-тестам; альтернатива «делать всё в cli» — разносит логику дайджеста по двум модулям.

### D2: вход сводки — уже напечатанный дайджест + план, через wrap_untrusted
Промпт получает детерминированный текст (он и так перед глазами пользователя) и JSON `[{cpv, tier}]`; CPV — строки из чужих эбилд-каталогов, поэтому оборачиваются `injection.wrap_untrusted` (в `wrap_untrusted` уже лежит build.log-контент в incident-пути). Системная часть промпта требует 2–5 строк plain text без markdown и запрещает выдумывать числа. Ответ дополнительно очищается `ui.strip_ansi` и печатается `paint_llm_block`.

### D3: деградация молчаливая, ошибка LLM — локально в enrich
Пустой `cfg.endpoint` → `summarize=None` (блок отсутствует, тишина). `summarize` вызывается в `plan_digest` после сборки детерминированных строк и перехватывает собственные исключения локальным except (результат — `None`): при отказе LLM возвращается ровно тот текст, что и сегодня, warn не печатается. Внешний except план-фазы (`cli.py:356-357`) остаётся для прочих сбоев обогащения — так отказ LLM не маскируется под «всё обогащение упало».

### D4: бюджет времени — общий timeout конфига, без отдельного ключа
Один синхронный вызов с `cfg.timeout`; план-фаза и так интерактивна (вопрос «Proceed?» позже), отдельный `plan_summary_timeout` — раздувание схемы, и так расходящейся со спеком (M10).

## Risks / Trade-offs

- Лишняя задержка перед вопросом `-a`: mitigation — один короткий вызов, timeout конфига, отсутствие вызова без endpoint.
- Галлюцинации в сводке («gcc — самый рискованный пакет»): mitigation — промпт «не утверждай того, чего нет во входе», числа не берутся из LLM, блок визуально отделён от ядра окраской.
- Инъекция через имена пакетов в оверлеях: mitigation — D2 wrap_untrusted + scan() трипваер.
- Тесты не должны требовать сети: D1 фейк-колбэк.

## Migration Plan

Обратная совместимость: без endpoint поведение байт-в-байт прежнее; потребители stdout-скриптов увидят новый блок только при активном endpoint — для машинного разбора существует `-p` вывод emerge, не дайджест.
