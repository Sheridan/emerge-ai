# Design

## Context

`run_tool_loop` (src/emerge_ai/llm.py:107-147) крутит раунды «ответ →
инструменты» и на исчерпании раундов поднимает безымянный `LLMError`
(llm.py:147); ответ эндпоинта с усечённым генерированием приходит с
`finish_reason == "length"` в `Response.finish_reason` (llm.py:26, 90) и
сейчас неотличим от нормального финального ответа. Единственный потребитель
ошибок — широкий `except Exception` в `_maybe_agent` (cli.py:140-142),
печатающий `agent unavailable: {exc}`. Признак интерактивности уже вычислен в
cli и прокинут в агента (cli.py:307-308); канал вопросов оператору описан
базовой спекой «Режимный канал вопросов оператору».

## Goals / Non-Goals

- Goals: различать «упёрлись в лимит» и «агент сломался»; в интерактиве —
  осмысленный вопрос, в неинтерактиве — логичное завершение; коды выхода
  emerge не трогаются ни в одном из режимов.
- Non-Goals: бюджеты/квоты на токены, подсчёт стоимости, автоматический
  retry без участия оператора, изменение протокола эндпоинта.

## Decisions

- **D1. Отдельный тип `LimitExhausted(LLMError)` с причиной `tokens|rounds`.**
  Поднимается при `finish_reason == "length"` и на превышении раундов.
  Альтернатива — флаг в `Response`: отвергнута, цикл продолжил бы работать с
  усечённым ответом, сигнал обязан прервать цикл.
- **D2. Вопрос оператору — тем же режимным каналом** (палитра нумерованных
  вариантов на stdin): продолжить / свернуть / завершить. В неинтерактиве
  вопрос запрещён базовой спекой канала. Альтернатива — авто-продолжение N раз:
  молча тратит чужой бюджет токенов, отвергнуто.
- **D3. Семантика вариантов.** «Продолжить» — то же состояние разбора,
  увеличенный бюджет раундов, максимум одно продолжение на разбор; «свернуть»
  — перезапуск с укороченным хвостом лога и ограничением результатов
  инструментов; «завершить» — advisory-вывод того, что уже собрано.
  Альтернатива «полный перезапуск с теми же параметрами» упрётся в тот же
  лимит.
- **D4. Нотисация в неинтерактиве = аудит-запись в `decisions.log`**
  (тот же канал, что у гейта: src/emerge_ai/gate.py:15) + развёрнутая строка
  в stderr. Альтернатива — отдельный `limits.log`: второй файл с тем же
  содержанием не нужен.
- **D5. Все прочие исключения — как сейчас.** `LimitExhausted` перехватывается
  в `_maybe_agent` до общего `except Exception`; ветка лимита не меняет код
  выхода, ошибка агента остаётся ошибкой агента.

## Risks / Trade-offs

- [Эндпоинт не выставит `finish_reason=length` и оборвёт ответ молча] →
  сетевые/HTTP-ошибки остаются обычным исключением (нынешнее поведение),
  а зависание цикла по-прежнему отсекается лимитом раундов, который теперь
  тоже даёт `LimitExhausted`.
- [Продолжение после усечения даст «склеенный» proposal] → продолжение —
  только по явному выбору оператора; усечённый фрагмент помечается в промпте
  как незавершённый.
- [Пересечение с wire-agent-apply-loop в `_maybe_agent`] → фиксированный
  порядок landing; внутри петли применения `LimitExhausted` трактуется как
  «вариантов нет» — применение не запускается.
