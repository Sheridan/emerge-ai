# Design

## Context

- Источники и отбор готовы: `changelog.collect_digest` (`changelog.py:111-151`) собирает news/GLSA/GitHub/git, при `client=None` возвращает сырой перечень, недоступные источники помечает; `llm_digest` (`changelog.py:98-108`) отбирает важное через LLM.
- Вызов один — ручная команда: `cli.py:296-297` → `_changelog_mode` (`cli.py:238-250`), где клиент конструируется только при `cfg.endpoint`, вывод — `ui.paint_llm_block`.
- Хук после прогона уже есть: `_post_run_digest` (`cli.py:229-236`) вызывается при `rc == 0` в обеих merge-ветках (`cli.py:322`, `cli.py:423`) и печатает `digest.post_run_digest` при `cfg.post_run_digest`.
- Отчёт прогона — `RunState` (`state.py:41-51`), сериализуется `save_run` через `asdict` (`state.py:74-80`); `load_run` (`state.py:83-85`) принимает только известные поля, новых ключей пока никто не пишет.
- Источники управляются конфигом: `cfg.gh_repos`, `cfg.git_urls`, `cfg.news_dir` (`config.py:23-24, 48-49`); ключа `changelog_digest` в `DEFAULTS` нет; расхождение имён ключей спека/кода — тема `align-config-schema` (M10).

## Goals / Non-Goals

**Goals:**
- Автоматический changelog-дайджест после успешного прогона под опцией `changelog_digest` (default false).
- Дайджест в отчёте прогона (JSON-отчёт остаётся единственным хранилищем).
- Никакого изменения кода возврата и вывода прогона при выключенной опции.

**Non-Goals:**
- Per-package сопоставление upstream-репозиториев из metadata.xml/оверлеев — источник остаётся декларативным списком конфига.
- Подключение источника «диффы USE» в `collect_digest` (существующий `use_diff`, `changelog.py:39-47`, сейчас никем не вызывается) — вне объёма.
- Пересмотр схемы конфига (M10) и ручной команды `--changelog`.

## Decisions

### D1: опция `changelog_digest`, default false
Внешние источники = сетевые запросы и git clone после каждого прогона; по умолчанию это неприемлемо, поэтому false. Имя — из спекового словаря ключей (M10), плоское, как сосед `post_run_digest`; алиасы/неймспейсы решает `align-config-schema`, не мы. Альтернатива default true — нарушила бы принцип «emerge-ai не ходит в сеть без явного согласия».

### D2: интеграция в `_post_run_digest`, а не новая точка в main
Шаг changelog добавляется в `_post_run_digest` после существующего post-run дайджеста: обе merge-ветки (`cli.py:322`, `cli.py:423`) получают его бесплатно, инцидентные прогоны — нет (changelog про успешные сборки). Клиент — только при `cfg.endpoint` (паттерн `_changelog_mode`). Весь шаг под `try/except Exception` с warn в stderr: обогащение не должно менять код возврата emerge (тот же принцип, что у план-фазы `cli.py:356-357`). Альтернатива — отдельная функция после `state.transition(DONE)` — дублирует загрузку конфига.

### D3: поле `changelog` в `RunState`
`changelog: str | None = None`; пишет `save_run` (он уже вызывается сразу после `_post_run_digest` — `cli.py:323`, `cli.py:424`). `load_run` на старых отчётах даёт `None` (default), обратная совместимость без миграций. Sidecar-файл на прогон отвергнут: два источника правды об одном прогоне.

### D4: контекст прогона для LLM-отбора — параметр `packages`
`collect_digest(..., packages: list[str] = ())` → прокидывается в `llm_digest` как перечисление «собрано в этом прогоне: <CPV>» в user-части промпта; источники не фильтруются (в v1 сопоставления пакет→репозиторий нет). Так отбор фокусируется на собранных версиях, а список «для каждого пакета» из спека перестаёт быть фиктивным. Пустой `packages` (ручной `--changelog`) — поведение побайтно прежнее.

## Risks / Trade-offs

- Задержка после прогона (сеть + git clone до timeout'ов): mitigation — только при включённой опции, недоступные источники уже деградируют в перечень, а не в ошибки.
- Ложная ассоциация «релиз X относится к собранному пакету» при декларативных gh_repos: mitigation — D4 передаёт перечень прогона в промпт, системный промпт и так требует цитировать источник каждого пункта.
- Разрастание `RunState` текстом дайджеста (отчёты и так с output_tail): mitigation — сохраняется ровно тот текст, что напечатан (LLM-отбор — короткие bullets), без ANSI (`ui.strip_ansi`).
- Конфликт имён ключей с M10: mitigation — имя взято из спека, при переименовании схемы достаточно правки одной строки DEFAULTS.

## Migration Plan

Опция выключена по умолчанию — апгрейд не меняет поведение никого. Включившие `changelog_digest` получают новый блок в stderr/stdout после прогона и новое поле в JSON отчёта; потребители отчётов (никто в репозитории не парсит) читают доп. поле опционально.
