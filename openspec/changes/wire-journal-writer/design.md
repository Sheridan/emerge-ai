# Design

## Context

Модуль журнала готов и покрыт тестами: нормализация текста ошибки и отпечаток
(`journal.fingerprint`, src/emerge_ai/journal.py:37),writer `record`
(journal.py:41) с обязательными полями, `finalize` (journal.py:53), который
пропускает только `success and verified_by`, и читатель `find` (journal.py:84).
Читающая сторона уже встроена в агента: перед разбором сбоя он вычисляет
отпечаток от `stderr_tail + class` (agent.py:400) и подмешивает прецедент в
промпт (agent.py:399-406). Empty journal → пустой `find` → дедуп всегда
промахивается (REVIEW_NOTES H4). Пишущая сторона требует три факта, которые
появляются только в петле применения `wire-agent-apply-loop`: применённое
действие, `run_id` прогона и код повторного merge (задание 2.3 того изменения).

## Goals / Non-Goals

- Goals: журнал наполняется единичной записью на подтверждённый фикс; связь
  аудит-комментариев правок с журналом;spec-путь совпадает с реальным.
- Non-Goals: ротация/архивация журнала, скоринг полезности прецедентов,
  запись неудач («неудачные решения записаны быть не могут» — базовая спека).

## Decisions

- **D1. Момент записи — повторный merge с кодом 0.** `finalize` вызывается из
  ветки успеха повтора (cli.py после `rc == 0`), `verified_by` описывает этот
  повтор (команда + код). Альтернатива — писать сразу после применения
  варианта: нарушает требование «только успешные», фикс может не починить сборку.
- **D2. Путь журнала в спеке — `/var/log/emerge-ai/journal.jsonl`.** Код и
  тесты единообразно используют его (journal.py:13), там же лежит аудит
  `decisions.log` гейта (gate.py:15). Альтернатива — перенос файла в
  `/var/lib/emerge-ai/journal`: лишняя миграция без выигрыша, лог-каталог
  уже согласован с аудитом.
- **D3. Ключ связи — `run_id`.** Записи журнала не имеют отдельного id
  (journal.py:42), прогон уже уникален и есть у обеих сторон; он и попадает в
  `journal_id` правок `config_edit`/регистраций `overlay`. Альтернатива —
  uuid на запись: требует менять формат записи и читателя ради поля, которое
  и так различает записи.
- **D4. Сбой журнала не влияет на прогон.** Ошибка записи — предупреждение в
  stderr после успешного merge; читающая сторона при отсутствующем или битом
  файле уже возвращает пустоту (journal.py:91-92). Альтернатива — ненулевой
  код при неудачной записи: наказывает пользователя за каталог логов, когда
  система уже починена.

## Risks / Trade-offs

- [Ошибочный отпечаток склеит разные сбои → неверный прецедент] → отпечаток
  считается от нормализованного «интересного» текста ошибки (journal.py:22-34)
  и в промпте помечается как подсказка, а не инструкция; агент всё равно
  строит варианты заново.
- [Журнал растёт, `find` читает файл целиком] → JSONL-дописывание линейно,
  файл читается только при сбоях; при росте — отдельное изменение про ротацию.
- [Пересечение с wire-agent-apply-loop в одном месте cli.py] → фиксированный
  порядок landing: сначала петля, этот писатель добавляет один вызов в её
  ветку успеха.
