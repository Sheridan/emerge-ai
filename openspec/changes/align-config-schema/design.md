# Design

## Context

Спецификация (`config-prompts` :9) — канон: `show_digest`, `etc_update_after_build`,
`changelog_digest`, `agent.web_access` (вкл. по умолчанию). Код: `Config.web_access/
etc_update_llm/post_run_digest` — плоские поля-дефолты в dataclass
(`src/emerge_ai/config.py:41-46`), `from_dict` фильтрует по `DEFAULTS`
(`:65`), неизвестное — `ignoring unknown key` (`:59-61`); для ключей спецификации это
тихий no-op + шум. `changelog_digest` в коде нет. `_REMOVED_KEYS`
(`config.py:28-30`, `reasoning_show`) — отдельный, уже работающий механизм «ключа больше
нет». README (`:81-88,93,163-164`) описывает имена кода; `packaging/emerge-ai.json.default`
содержит лишь 4 ключа.

## Goals / Non-Goals

**Goals:** конфиг, написанный по спецификации, работает; старый конфиг работает как раньше,
с предупреждением переименования; один канон в коде, README и шаблоне.

**Non-Goals:** миграция/переписывание пользовательских файлов на диске, новые настройки,
реализация потребителя `changelog_digest` (change `auto-changelog-digest`), изменение
прав/пути конфига.

## Decisions

**D1. Канон = имена спецификации; алиасы разбираются в `from_dict`.**
Поля dataclass переименовываются в `show_digest`/`etc_update_after_build`/
`changelog_digest`; файл читается через нормализацию `_ALIASES`, поле `web_access`
остаётся плоским атрибутом (значение из `agent.web_access`), чтобы не трогать все места
чтения. Альтернатива — вложенный атрибут `cfg.agent.web_access`: отвергнута, точечный
резолвинг словаря — забота разбора, не модели данных. Альтернатива — оставить старые поля,
добавив маппинг на входе: отвергнута, расхождение кода и спецификации сохраняется
навсегда.

**D2. Таблица алиасов + приоритет канонического имени.**
`_ALIASES = {"post_run_digest": "show_digest", "etc_update_llm": "etc_update_after_build",
"web_access": "agent.web_access"}`; каждый сработавший алиас — `warn("... is deprecated,
use ...")` (стиль существующих предупреждений); если заданы оба имени — берётся канон,
алиас игнорируется тоже с предупреждением. Альтернатива — молчаливые алиасы: отвергнута,
имена никогда не мигрируют. Альтернатива — жёсткая ошибка при старом ключе: отвергнута,
рабочая машина не должна падать из-за переименования. Невалидный тип `agent` (не объект) —
предупреждение + дефолты, как с прочим мусором в конфиге.

**D3. `changelog_digest`: default `true`, поле есть, потребитель позже.**
Остальные дайджест-флаги включены по умолчанию (`post_run_digest: True`), changelog и так
печатается по запросу — включённый default сохраняет текущее поведение и задаёт контракт
для `auto-changelog-digest` (M11). Альтернатива — `false` (opt-in): отвергнута, M11 тогда
менят поведение по умолчанию, а не добавляют флаг.

**D4. Шаблон и README — канонические ключи.**
`packaging/emerge-ai.json.default` дополняется `show_digest`, `etc_update_after_build`,
`changelog_digest`, `agent: {"web_access": true}`; README-пример и список ключей — те же
имена, «Дайджесты» — `show_digest` + `changelog_digest`. Альтернатива — минимальный
шаблон как сейчас: отвергнута, файл должен быть самодокументируемым, а существующие
конфиги обновлений не затрагивает (README `:35-37`: шаблон меняется, файл пользователя —
нет).

## Risks

- [Риск] Развёрнутые конфиги со старыми ключами «зашумят» предупреждениями → митигация:
  предупреждение — единственный эффект, поведение сохранено (алиасы); это цель, а не баг.
- [Риск] M11 решит, что авто-дайджест должен быть выключен по умолчанию → митигация:
  default зафиксирован дельтой спецификации, изменение — отдельное изменение spec.
- [Риск] Тесты/скрипты пишут старый `web_access` → митигация: алиас совместим; тесты
    обновляются в задачах, `tests/test_config.py:10` (`cfg.web_access is True`) проходит
    и на вложенном, и на плоском виде.
