# Design

## Context

Мотивация — в proposal.md (Why). Состояние кода, важное для подхода:

- Единственные «видимые» строки самого emerge-ai — точечные `ui.info` (агент-консультация,
  autonomy gate, resume). `runner.run_emerge_capturing`, `llm.LLMClient.chat`,
  `agent.IncidentAgent._dispatch`, `whitelist.execute`, `rollback` и `sandbox` исполняют
  внешние действия молча.
- Флаг `-v` уже определён (`cli.VERBOSE_FLAGS` + `flag_present`, кластеры) и доезжает до
  почти всех LLM-клиентов как kwarg `show_reasoning` (исключение — `_post_run_digest`).
- Инварианты: stdout обычных merge-прогонов — байт-в-байт pass-through вывода emerge
  (spec: console-output, run-reporting); весь собственный вывод — в stderr; pipe без
  escape-кодов; codes выхода неприкосновенны.

## Goals / Non-Goals

**Goals:**

- Одна точка объявления активности для всех внешних действий; уровень по умолчанию +
  детализация при `-v` без новых ключей конфига.
- Дамп запроса к эндпоинту при `-v` — на каждом LLM-вызове, включая будущие новые
  call-site'ы, без их ручной проводки.

**Non-Goals:**

- Вывод рассуждений модели (изменение `fix-verbose-thinking-output`), язык ответов
  (`fix-llm-response-language`); лог-файл/журнал активности, уровни `--quiet`, JSON-релоги;
  аннотации поверх stdout emerge.

## Decisions

### D1. Два уровня активности без глобального состояния verbosity

Строки анонса печатаются ВСЕГДА (это и есть «пользователь видит, чем занято приложение»).
Детализация при `-v` (тело запроса, длительность) живёт только в `LLMClient`, куда verbose
уже доезжает флагом конструктора — нового глобального состояния не нужно.
Альтернатива — модульный флаг `ui.set_verbose()`: отвергнута, анонсы от verbose не зависят,
а verbose-зависимые детали точечно живут в одном клиенте.
Альтернатива — анонсы только под `-v`: отвергнута, против запроса «пользователь должен
видеть» и не противоречит console-output (stderr, info-стиль без акцента).

### D2. Общий хелпер `ui.activity()`, места вызова явные

Новый хелпер в `ui.py` поверх `info` (тот же поток stderr, префикс, plain в pipe). Вызывается
явно в: `runner.run_emerge_capturing` (полный argv), `whitelist.execute` (emaint/deselect),
`rollback` (btrfs и пр.), правки `config_edit` (какой файл/строка),
`sandbox` (journal/pretend/web_fetch), `agent._dispatch.call` (аргументы — срезанные до ~200
символов). Тривиальные пробы (`prompts._run`: findmnt, `/proc`) анонсов НЕ получают —
отдельный молчаливый seam.
Альтернатива — единая обёртка над subprocess: отвергнута, у sandbox/whitelist/rollback
разная семантика (capture, env, timeout); общего только объявление.

### D3. `chat()` — единственная точка видимости обращений к LLM

`LLMClient.chat()` оборачивает весь цикл вызова: до запроса — анонс `отправляю запрос к LLM
(model=…, N сообщений, tools=M)`; при verbose — дамп JSON payload (cap константой модуля с
плашкой `[capped …]`, значения `api_key` заменены на `***`, заголовки не дамперятся); после —
`ответ LLM за X.Xs (finish=…)`. Так молча покрываются consent, etcupdate, changelog,
summarize, news — любые будущие call-site'ы получают видимость без проводки.
Альтернатива — анонс в каждом call-site: отвергнута, новые места забудут.

Флаг конструктора `show_reasoning` переименовывается в `verbose`: он теперь включает не
только рассуждения. Механическая правка ~10 мест + тестов. Альтернатива — оставить имя:
отвергнута, имя станет врать.

### D4. Секреты в дампах

Дамперится только payload (`/chat/completions` body), никогда заголовки; если `api_key`
задан, все вхождения его значения в дампе заменяются `***` (паранойя: ключ мог попасть в
текст сообщений). Cap и плашка — тот же паттерн, что severity-срез plan-triage.

## Risks / Trade-offs

- [Шум в stderr ломает существующие тесты, сверяющие stderr] → обновление фикстур
  `test_cli`/`test_llm`/`test_runner` в рамках tasks; регрессии pass-through stdout
  (`split-emerge-stderr`) держат тесты неизменными — stdout не трогается вовсе.
- [Verbose-дамп содержит приватный текст логов/конфигов, ушедших в модель] → осознанное
  поведение `-v`, только stderr, на диск не пишется; задокументировать в README.
- [Анонсы tool-call'ов выводят аргументы с путями/URL на терминал] → это и есть цель;
  секреты там не живут (ключ — только в заголовке), кап 200 символов защищает от простыней.
- [Переименование `show_reasoning` → `verbose` заденет внутренние сигнатуры] → публичный
  CLI-контракт (`-v`) не меняется; тесты обновляются тем же коммитом.

## Migration Plan

Схемы конфига и файлы состояний не меняются; обновление — обычная переустановка пакета.
Откат — откат коммита: поведение деградирует до текущего молчаливого, без миграций данных.

## Open Questions

- Точный cap дампа payload (8 КБ или 4 КБ) и формат строки длительности — решаются на
  implementation, на спеки не влияют.
